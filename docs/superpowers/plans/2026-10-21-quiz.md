# 퀴즈 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 글마다 딸린 문제와 용어 사전에서 만든 문제를 말해보카처럼 풀고, 틀린 문제와 오래된 문제가 다시 나오게 한다.

**Architecture:** 문제는 글마다 YAML 파일(`src/content/quizzes/{domain}/{slug}.yaml`)로 쓰고, 빌드할 때 용어 문제와 합쳐 문제 은행 JSON(`quiz/bank.json`)으로 낸다. 채점·다시 나오는 규칙·저장은 순수 함수(`src/lib/quiz/`)로 두고, 풀이 화면은 그 함수를 쓰는 바닐라 스크립트(`src/scripts/quiz.ts`)가 그린다. 기록은 localStorage에만 둔다.

**Tech Stack:** Astro 7(정적 엔드포인트), zod, yaml, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-domain-basics-and-quiz-design.md` 6장(퀴즈), 4.2의 8번(글 끝 카드), 4.4(홈 퀴즈 카드), 11장(정할 것).

## Global Constraints

- 문제 형태는 OX, 객관식(4지), 주관식 셋. 문제마다 해설(해요체, 문장 80자, 단락 3문장 검사)이 있다. 문제 글은 물음으로 끝나도 된다.
- 주관식은 정답을 여러 개 둘 수 있고, 대소문자·띄어쓰기·하이픈을 무시한다. `term`을 적으면 그 용어의 `name`과 `aliases`도 정답이다.
- 용어 문제는 자동: "뜻 → 용어"(주관식), "용어 → 뜻"(객관식, 오답 보기는 같은 영역의 다른 용어 뜻). 영역 용어가 4개보다 적으면 객관식은 만들지 않는다.
- 문제마다 바뀌지 않는 키. 지운 문제의 기록은 무시한다.
- 상자 1~5, 맞히면 한 칸 위, 틀리면 1. 간격 1·3·7·14·30일. 한 번에 10문제, 다시 볼 문제 먼저, 남는 자리는 처음 보는 문제.
- 기록은 localStorage만. 쓸 수 없어도 문제는 풀린다. 저장 키에 버전을 둔다.
- 퀴즈 페이지는 검색 색인에서 뺀다(`data-pagefind-body`를 두지 않는다). 내부 링크는 `src/lib/paths.ts`의 함수로 만든다.
- 360px에서 가로 넘침이 없고, 키보드로 풀 수 있다(숫자 키로 고르기, Enter로 다음). 디자인은 지금 카드·버튼·색. 정답은 강조색, 오답은 경고색.
- 서브 에이전트는 쓰지 않는다.

## 정한 것 (스펙 11장)

| 항목 | 정한 값 |
| --- | --- |
| 문제 파일 | `src/content/quizzes/{domain}/{slug}.yaml`, 파일 경로가 곧 글 id. 테스트는 `QUIZZES_CONTENT_DIR` |
| 문제 키 | 글 문제 `{글 id}#{문제 id}`, 용어 문제 `term:{영역}/{용어 id}#def`(뜻→용어), `#pick`(용어→뜻) |
| 주소 | 퀴즈 홈 `quiz/`, 풀이 `quiz/play/?scope=…`(due, new, domain:{id}, doc:{글 id}), 문제 은행 `quiz/bank.json` |
| 저장 | localStorage 키 `domaindocs.quiz.v1`, 값 `{ "v": 1, "records": { [문제 키]: { "box": 1~5, "due": "YYYY-MM-DD", "right": n, "wrong": n } } }` |
| 날짜 | 사용자 기기의 날짜 기준. `due`가 오늘이거나 지났으면 다시 볼 문제 |

## Review Focus

1. 저장소를 쓸 수 없는 브라우저(예외를 던지는 localStorage)에서 풀이가 끝까지 되고 오류가 나지 않아야 한다.
2. 깨진 저장 값(JSON이 아님, 다른 버전)이 있어도 빈 기록으로 시작해야 한다.
3. 용어의 `short`에 그 용어 이름이 들어 있으면 "뜻 → 용어" 문제는 답이 보이므로 만들지 않아야 한다.
4. 문제가 하나도 없는 범위(예: 다시 볼 문제 0개)로 들어오면 빈 화면 대신 안내와 다른 풀기 링크가 나와야 한다.
5. 주관식에 앞뒤 공백·전각 문자·대문자를 섞어 넣어도 맞게 채점되어야 한다.

### Task 2: 채점·문제 은행·다시 나오는 규칙·저장 (순수 함수)

**Files:**
- Create: `src/lib/quiz/{answer,bank,schedule,storage}.ts`, `tests/unit/quiz-*.test.ts`

**Interfaces:**
- `normalizeAnswer(s: string): string` — NFKC, 소문자, 공백·하이픈·밑줄 제거.
- `isInputCorrect(input: string, accepted: readonly string[]): boolean`
- `type QuizQuestion = { key; domain; docId?; type: 'ox'|'choice'|'input'; prompt; choices?: string[]; answer: boolean|number|string[]; explain; link: { url; title } }`
- `termQuestions(terms: GlossaryTerm[], docTitle: (id) => string|undefined, urls): QuizQuestion[]` — `#def`는 `short`에 이름이나 별칭이 들어 있으면 만들지 않는다. `#pick`은 영역 용어 4개 이상일 때, 오답 3개를 키로 정해지는 순서(문자열 해시)로 고른다. 보기 위치도 해시로 정한다(빌드마다 같다).
- `buildBank(docQuizzes, terms, docs): QuizQuestion[]` — 없는 글을 가리키면 오류를 던진다.
- `BOX_DAYS = [1, 3, 7, 14, 30]`, `applyResult(rec | undefined, correct: boolean, today: string): QuizRecord`, `isDue(rec, today): boolean`, `addDays(date: string, n): string`
- `pickSession(bank, records, scope: Scope, today, rng = Math.random, size = 10): QuizQuestion[]` — `Scope = {kind:'due'} | {kind:'new'} | {kind:'domain', id} | {kind:'doc', id}`. due는 오래 밀린 순, new는 섞어서.
- `loadRecords(storage?: Storage): Records`, `saveRecords(records, storage?)`, `pruneRecords(records, keys: Set<string>)`, `dueCount(records, keys, today)` — 모두 예외를 삼킨다.

- [ ] Step 1: 테스트를 쓴다. 채점(공백·대소문자·하이픈·전각), 상자 이동(1→2, 5에서 맞혀도 5, 틀리면 1)과 due 날짜, pickSession 순서와 범위·크기, 용어 문제(이름이 든 뜻은 건너뜀, 3개 영역은 객관식 없음, 오답이 같은 영역), 저장(깨진 JSON, 다른 버전, 던지는 storage).
- [ ] Step 2: 실패 확인 → Step 3: 구현 → Step 4: `npm test` 통과 → Step 5: 커밋.
