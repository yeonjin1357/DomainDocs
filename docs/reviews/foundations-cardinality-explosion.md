원문은 직접 받아 읽었어요. Prometheus 문서는 prometheus.io의 현재 페이지와 v3.15.0 태그의 `docs/`를 함께 봤어요. 현재 페이지에도 3.15.0에 새로 생긴 `stale_series_compaction_threshold`가 있어서 같은 판이에요. 소스는 v3.15.0 태그에서 직접 받았어요(App.tsx, TSDBStatusPage.tsx, QueryPanel.tsx, web/api/v1/api.go, cmd/prometheus/main.go, tsdb/head.go, tsdb/db.go, scrape/scrape.go, scrape/target.go, scrape/metrics.go, model/relabel/relabel.go, config/config.go). OpenTelemetry 명세 4쪽과 Grafana Cloud 청구 문서도 원문으로 확인했어요.

PromQL과 설정은 컨트롤러가 받아 둔 promtool 3.15.0(revision 5241a27)으로 확인했어요. 글의 코드 블록 7개를 스크립트로 그대로 꺼냈어요. `check config` 2개와 `check rules` 1개가 SUCCESS였어요. `test rules` 시험 2개(글의 질의를 같은 글자로 넣음)도 SUCCESS였어요. 일부러 틀린 기대값을 넣은 대조 시험은 FAILED(exit 1)라, 시험이 실제로 값을 비교해요.

promtool로 못 보는 동작은 이미 받아 둔 Prometheus 3.15.0(같은 revision)을 띄워 확인했어요. 수집 주기 2초로 node 시험 대상을 수집했어요. job은 `api`(경로 틀 → 배포 버그로 실제 경로 → 고침 순서로 바꿈), `topk`, 글의 `drop` 설정, `sample_limit`·`label_limit`·`label_value_length_limit` 초과, `labeldrop` 겹침이에요. 실험 뒤 서버와 시험 대상은 모두 껐어요. 아래 "실험"은 이 결과예요.

연결된 글: time-series-and-labels.mdx(카디널리티 정의, OpenTelemetry 2,000 상한과 overflow, `labeldrop` 경고, `sample_limit`)와 logs-metrics-traces.mdx(ID는 트레이스·로그로)와 어긋나는 곳은 찾지 못했어요. empty-graph.mdx 118행("`metric_relabel_configs`로 버린 값은 세지 않아서")과 alert-conditions·alert-fatigue의 "결과가 비면 울리지 않음"과도 같아요.

## 반영

- Grafana Cloud 요금 문장: 반영. 문장과 sources 항목을 뺐어요. 그 자리에 `prometheus_tsdb_head_series`를 넣어, 그릴 지표를 바로 알 수 있게 했어요.
- 1단계 질의와 화면의 세는 기준: 반영. 질의 경고 단락 뒤에 두 문장을 더했어요("지금 값이 들어오는 시계열만 세서…", "화면은 모든 서비스를 세고…").
- 2단계 `topk`: 반영. `bottomk`로 바꾸고, 주석과 본문("늘어난 값은 값마다 시계열이 적어서 적은 순으로 봐요")도 고쳤어요. promtool 3.15.0 `test rules`로 다시 확인했어요. 경로 틀 2개(시계열 6·3개)와 ID 경로 2개(각 1개)를 섞으니, `bottomk(2, …)`는 ID 경로 둘을, `topk(2, …)`는 경로 틀 둘을 돌려줬어요. `job="web"` 시계열은 섞이지 않았어요.
- (선택) `labeldrop` 겹침: 반영. "값 하나만 남고 나머지는 오류 없이 사라져요"를 넣었어요.
- (선택) head block 정리 시간: 반영. 3단계 확인 방법을 "몇 시간 높게 남을 수 있어요"로 바꿨어요.
- (선택) 수집 대상 풀이: 반영. "Prometheus가 값을 가져가는 서버"로 주어를 밝혔어요.
- (선택) `label_limit`에 `__name__`·`job`·`instance`도 세는 점: 반영 안 함. 예시 한도 30에서는 판단이 바뀌지 않고, 본문 분량을 아끼려고요.
- 가독성 검토도 함께 반영했어요. 3단계 `drop` 설정과 4단계 알림 규칙에는 줄마다 주석을 달았어요. promtool `check config`와 `check rules`는 둘 다 SUCCESS예요.
