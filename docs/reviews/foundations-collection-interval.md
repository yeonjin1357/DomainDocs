# 사실 검토: 수집 방식과 수집 주기

- 글: src/content/docs/foundations/collection-interval.mdx
- 검토일: 2026-10-13
- 결과: 수정 필요 3건 / 확인 49건

계산은 node로 다시 했어요. `promql/functions.go`(v3.15.0)의 `extrapolatedRate` 중 실수·카운터 경로를 그대로 옮겼어요(시작 시각 기능은 기본으로 꺼져 있어 뺐어요). 40% 바탕에 3초 동안 100%인 스파이크를 넣은 CPU 시간 카운터를 15초마다 수집해 돌렸어요. 아래 "직접 실행"은 모두 이 결과예요.

43%/44% 정리: 그림·본문·더 깊이의 숫자는 서로 맞아요. 그림과 본문의 43%는 60초 떨어진 두 샘플로 구한 값이에요. Prometheus 3에서 1분 간격 점에 `[75s]`로 그려도 늘 43%예요. 75초는 점 간격 1분, 수집 15초일 때 Grafana `$__rate_interval` 값이에요. `rate(...[1m])`를 1분 간격 점으로 그리면 스파이크 위치에 따라 결과가 갈려요. 1분 안의 위치 중 70%는 44%, 20%는 40%, 10%는 그 사이 값이에요. 40%가 나오는 20%에서는 스파이크가 어느 점에도 안 남아요. 더 깊이는 44% 경우만 말해서 오해 소지로 판정했어요. 15초 간격 점이면 어느 위치든 최고 44%가 한 번은 보여요.
