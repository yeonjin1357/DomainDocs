<Deeper>
  ### 계산 방법

  가장 단순한 계산법은 nearest-rank(가장 가까운 순위) 방식이에요. 값을 오름차순으로 정렬하고, 아래 순위에 있는 값을 골라요.

  ```text
  순위 = ⌈p × n / 100⌉   (⌈ ⌉는 올림, n은 요청 수)
  ```

  요청 100개의 p99는 99 × 100 / 100 = 99번째 값이에요. 요청 50개의 p99는 ⌈49.5⌉ = 50번째, 곧 최댓값이에요.

  코드에서는 p × n을 먼저 곱하고 100으로 나눠요. 100으로 먼저 나누면 부동소수점 오차로 순위가 밀릴 수 있어요. JavaScript에서 99.9 / 100 × 1000은 999.0000000000001이라, 올림하면 1000이 돼요.

  NumPy와 R은 기본으로 앞뒤 순위의 값 사이를 보간해요. 요청이 적고 꼬리가 길면 도구마다 p99가 크게 달라져요.

  요청 50개 중 49개가 160ms, 1개가 3초라고 해 봐요. p99는 nearest-rank로 3,000ms, NumPy 기본값으로 1,608ms예요.

  ### 히스토그램과 summary

  Prometheus 클래식 히스토그램은 미리 정한 구간(bucket)마다 요청 수를 세요. 버킷은 누적이라서, `le="0.5"` 버킷에는 0.5초 이하인 요청이 모두 들어가요.

  `histogram_quantile()`은 버킷 안에 값이 고르게 퍼져 있다고 보고 선형 보간해요. 그래서 결과는 근사값이고, 버킷 경계가 정확도를 좌우해요. 예를 들어 p99가 0.5~1초 버킷에 들면, 실제 p99는 그 사이 어디든 될 수 있어요.

  히스토그램은 여러 서버를 합칠 수 있어요. 서버별 버킷 카운터마다 rate(초당 증가량)를 먼저 구하고, 같은 `le`끼리 더한 뒤 p99를 계산해요. 이때 서버마다 버킷 경계가 같아야 해요.

  summary는 각 서버가 직접 계산한 p99 같은 값을 내보내요. 이 값끼리는 합칠 수 없어서, 여러 서버를 묶은 p99를 구할 수 없어요. `avg(http_request_duration_seconds{quantile="0.99"})`처럼 평균 내는 식도 틀려요.

  히스토그램으로 여러 서버를 합친 p99는 이렇게 구해요.

  ```text
  histogram_quantile(0.99, sum by (le) (rate(http_server_request_duration_seconds_bucket[5m])))
  ```

  `sum by (le)`는 `le`만 남기고 서버·경로 같은 다른 라벨을 모두 합쳐요. 서비스별로 보려면 `sum by (job, le)`처럼 남길 라벨을 더 적어요.
</Deeper>
