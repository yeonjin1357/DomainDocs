<KeyPoints>
  <Point title="안쪽부터 바깥으로 읽어요">
    PromQL 질의는 함수가 겹겹이 싸인 꼴이에요. 가장 안쪽에서 시계열을 고르고, 바깥으로 나오며 구간을 잡고, 계산하고, 묶어요.

    ```text
    sum by (job) (
      rate(
        http_requests_total{
          status=~"5.."
        }[5m]
      )
    )
    ```

    이 질의는 상태 코드가 5로 시작하는 요청을 고르고, 5분 구간의 초당 증가량을 구한 뒤, 서비스(`job`)마다 더해요.
  </Point>
  <Point title="중괄호는 시계열을 고르는 조건이에요">
    `{status=~"5.."}`처럼 레이블에 조건을 걸어 시계열을 골라요. 같은 지표 이름이라도 레이블 값마다 <Term slug="foundations/time-series-and-labels">시계열</Term>이 따로라서, 조건이 곧 어느 줄을 볼지예요.
  </Point>
  <Point title="by에 적은 레이블만 남아요">
    `sum by (job)`은 시계열을 더해 `job` 값마다 하나로 줄여요. `instance`, `status` 같은 나머지 레이블은 결과에서 사라져요.
  </Point>
</KeyPoints>

예시 데이터에는 api 서버 두 대(a, b)와 web 서버 한 대(c)가 있어요. 5xx 시계열은 a의 500, b의 503, c의 500, 이렇게 세 개예요. rate까지는 세 개 그대로이고, `sum by (job)`에서 api 두 개가 합쳐져 api 0.5건, web 0.05건이 돼요.

## 고르기: 지표 이름과 레이블 조건

지표 이름만 쓰면 그 이름의 시계열을 모두 골라요. 중괄호 안에 조건을 쉼표로 이어 붙이면 모두 맞는 것만 남아요.

| 조건 | 뜻 |
| --- | --- |
| `job="api"` | 값이 정확히 같아요 |
| `job!="api"` | 값이 달라요 |
| `status=~"5.."` | 정규식에 맞아요 |
| `status!~"5.."` | 정규식에 맞지 않아요 |

정규식은 값 전체와 맞아야 해요. `status=~"5"`는 `^5$`로 읽혀서, `500`이나 `503`은 고르지 않고 빈 결과가 나와요. 5로 시작하는 세 자리는 `"5.."`로 써요.

구간 없이 고른 결과(instant vector)는 시계열마다 가장 최근 값 하나예요. 기본으로 5분 안에 들어온 값만 쓰고, 그보다 오래된 시계열은 빠져요.

## 구간: [5m]

`[5m]`을 붙이면 시계열마다 최근 5분 동안의 값들을 모두 가져와요. 이걸 range vector라고 불러요. 이 결과는 그래프로 바로 그릴 수 없고, 함수에 넣어 숫자 하나로 바꿔요.

카운터라면 `rate`(초당 증가량)나 `increase`(구간 동안 늘어난 양)에 넣어요. 오르내리는 값(게이지)이라면 `avg_over_time`, `max_over_time`처럼 구간의 평균이나 최댓값을 구해요. 카운터를 읽는 원리는 <Term slug="foundations/counters-and-rate">카운터와 rate</Term>에 있어요.

## 묶기: sum, avg, max, count

집계 연산자는 여러 시계열을 하나로 묶어요. `sum`, `avg`, `max`, `min`, `count`가 흔하고, `topk(5, ...)`는 값이 큰 5개를 골라요.

`by (job)`은 적은 레이블만 남기고, `without (instance)`는 적은 레이블만 빼고 나머지를 남겨요. 둘 다 없으면 모든 시계열이 하나로 합쳐져요. 예시에서 `sum(rate(http_requests_total[5m]))`는 서비스 구분 없이 초당 25건 하나만 남아요.

## 나누기: 양쪽 레이블이 맞아야 해요

비율은 두 질의를 나눠 구해요. PromQL은 왼쪽과 오른쪽에서 레이블이 똑같은 시계열끼리 짝을 지어 계산해요. 짝이 없는 시계열은 결과에서 빠져요.

```text
sum by (job) (
  rate(x{status=~"5.."}[5m])
)
/
sum by (job) (
  rate(x[5m])
)
```

`x`는 `http_requests_total`을 줄여 쓴 거예요. 양쪽 모두 `job`만 남겨서 짝이 맞고, api 2.5%와 web 1%가 나와요. 왼쪽만 `by (job, status)`로 바꾸면 왼쪽에만 `status`가 있어서 짝이 하나도 없고, 결과가 비어요.

이럴 때는 `ignoring(status)`로 그 레이블을 빼고 짝을 짓게 해요. 한쪽 여러 줄이 다른 쪽 한 줄과 짝을 지으면 `group_left`도 붙여요. 그러면 api의 500은 1%, 503은 1.5%처럼 상태 코드마다 비율이 나와요.

## 모니터링에서는

그래프 패널은 같은 질의를 시각마다 되풀이해 계산한 값을 이어 그려요. 그래서 `[5m]` 구간과 그래프의 점 간격은 따로예요.

점 간격이 구간보다 길면 그 사이의 값은 계산에 들어가지 않아요. 구간을 잡는 기준은 <Term slug="foundations/collection-interval">수집 방식과 수집 주기</Term>에 있어요.

질의 결과가 비면 그래프도 비어요. 0이 아니라 데이터가 없는 거예요. 그 차이는 <Term slug="foundations/no-data-vs-zero">데이터 없음과 0은 달라요</Term>에서 다뤄요.

  <Check>비율 질의가 빈 결과를 낸다면 나누는 양쪽의 `by` 레이블이 같은지 보세요. 한쪽에만 남은 레이블이 있으면 짝이 없어 결과가 비어요.</Check>
  <Check>`=~` 조건이 아무것도 고르지 않는다면, 정규식이 값 전체와 맞는지 보세요. `"5"`는 `500`과 맞지 않아요.</Check>

  <Check>게이지에 `rate`를 쓰거나, 카운터를 `avg_over_time`으로 그렸다면 다시 보세요. 카운터인지 게이지인지 먼저 확인하세요.</Check>

<Deeper>
  ### 5분 조회 범위와 stale

  구간 없이 고른 값은 계산 시각에서 5분 안에 있는 가장 최근 값이에요. 이 5분을 lookback 범위라고 하고, 설정으로 바꿀 수 있어요. 수집 대상이 사라지면 Prometheus가 '더 이상 값이 없다'는 stale 표시를 남겨, 5분을 기다리지 않고 바로 빠져요.

  ### 구간의 경계

  Prometheus 3의 `[5m]`은 왼쪽이 열린 구간이에요. 계산 시각에서 정확히 5분 전에 들어온 값은 빼고, 계산 시각의 값은 넣어요.

  ### 비율을 서비스마다 나누기

  위의 `ignoring(status) group_left`는 왼쪽(상태 코드별 5xx)의 여러 줄을 오른쪽(서비스 전체)의 한 줄과 짝지어요. 결과에는 왼쪽의 레이블이 남아요. 반대로 오른쪽이 여러 줄이면 `group_right`를 써요.
</Deeper>
