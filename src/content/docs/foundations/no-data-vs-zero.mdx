<KeyPoints>
  <Point title="0은 '없었다', 데이터 없음은 '모른다'예요">
    0은 재 봤더니 값이 0이었다는 기록이에요. 에러율 0%라면 요청이 들어왔고, 그중 에러는 없었다는 뜻이죠.

    데이터 없음은 기록 자체가 없다는 뜻이에요. <Term slug="foundations/collection-interval">수집</Term>이 멈췄거나 서버가 내려갔을 수도, 아직 한 번도 기록하지 않은 값일 수도 있어요. 그래서 에러 0%는 좋은 소식이지만, 데이터 없음은 가장 나쁜 상황일 수도 있어요.
  </Point>
  <Point title="한 번도 안 생긴 시계열은 0이 아니라 없어요">
    Prometheus의 Go·Python 클라이언트에서 레이블이 붙은 지표는, 그 레이블 값 조합을 처음 쓸 때 <Term slug="foundations/time-series-and-labels">시계열</Term>이 생겨요. 요청 수를 `route`와 `status` 레이블로 세면, 에러가 한 번도 안 난 경로엔 `status="500"` 시계열이 없어요. 그래서 이 경로의 에러율 질의는 0%가 아니라 빈 결과를 돌려줘요.

    Prometheus 계측 문서는 생길 줄 아는 시계열을 미리 0 같은 기본값으로 내보내라고 권해요. 그러면 에러가 없을 때 진짜 0이 나와서, 빈 결과와 헷갈리지 않아요.
  </Point>
  <Point title="빈 값을 0으로 채우면 장애가 정상처럼 보여요">
    화면 코드가 빈 결과를 0으로 바꾸면, 수집이 멈춘 장애가 '에러 0%'로 보여요. 장애 한가운데서 가장 건강한 숫자가 떠서, 확인하러 갈 이유가 사라져요.

    빈 값은 빈 값대로 보여 줘요. 그래프는 그 구간의 선을 끊고, 숫자 칸에는 '데이터 없음'을 띄워요. Grafana Stat 패널(숫자 하나를 보여 주는 패널)은 기본으로 시간 범위의 마지막 값을 띄워, 멈추기 전 값이 장애를 가리기도 해요.
  </Point>
</KeyPoints>

<Checkpoints>
  <Check>빈 응답에 `?? 0`이나 `|| 0`을 붙여 0을 넣는 코드가 있다면 다시 보세요. Prometheus HTTP API는 결과가 없으면 `result`가 빈 배열이라, `result[0]?.value[1]`은 undefined예요. 두 식 모두 이걸 0으로 바꾸니, null(값이 비었다는 표시)로 두고 '데이터 없음'으로 그리세요.</Check>
  <Check>에러 수 ÷ 요청 수로 에러율을 구한다면, 요청이 0건일 때 '요청 없음'으로 보이는지 확인하세요. Prometheus에서 0 ÷ 0은 NaN(숫자가 아니라는 값)이고, API는 이를 문자열 "NaN"으로 보내요. 이 문자열을 `Number()`로 바꾼 뒤 `|| 0`을 붙이면 NaN도 0이 돼서, 요청이 없던 구간이 '에러 0%'로 보여요.</Check>
  <Check>알림이 데이터 없음을 정상으로 처리한다면 다시 보세요. Prometheus 알림 규칙은 식의 결과가 비면 울리지 않고, 울리던 알림도 해제돼요. Grafana 알림도 No Data 처리를 Normal로 두면 같고, 일부 시계열만 사라질 땐 기본 설정에서도 해제돼요.</Check>
  <Check>꼭 봐야 할 지표에 값이 끊긴 걸 알리는 알림이 없다면 더하세요. <Term slug="foundations/collection-interval">수집 목록에서 빠진 대상</Term>은 `up`(수집 성공 1, 실패 0)도 0이 아니라 사라져서, `up == 0` 알림이 놓쳐요. Prometheus의 `absent_over_time(up{job="api"}[10m])`은 10분 동안 값이 없으면 1을 내요.</Check>
</Checkpoints>

<Deeper>
  ### Prometheus에서 결과가 비는 경우

  PromQL(Prometheus 질의 언어)은 고른 시계열이 없으면 0이 아니라 빈 결과를 돌려줘요. HTTP API 응답은 성공(`success`)이고, `result`만 빈 배열이에요.

  `sum()` 같은 집계도 입력이 비면 결과가 비어요. 결과 시계열을 입력 시계열에서 만들기 때문이에요.

  `/` 같은 이항 연산(값 둘로 계산하는 연산)은 양쪽에서 레이블이 같은 짝끼리만 계산해요. 짝이 없는 시계열은 결과에서 빠져요. 그래서 `sum by (route)`로 경로별 에러율을 구하면, 에러가 한 번도 안 난 경로는 0%가 아니라 결과에서 빠져요.

  <Term slug="foundations/counters-and-rate">rate</Term>는 구간에 샘플(sample, 수집한 값 하나)이 2개 이상 있으면 값을 내요. 그래서 `[5m]`이면 수집이 멈추고도 5분 가까이 멈추기 전 샘플로 값이 나와요. 그림을 10분 뒤로 잡은 이유예요.

  0 ÷ 0은 IEEE 754(부동소수점 계산 표준) 규칙대로 NaN이에요. 에러와 요청 시계열이 모두 있는데 둘 다 늘지 않은 구간이 여기에 해당해요.

  ### 0으로 채우는 코드

  `sum(...) or vector(0)`은 왼쪽 결과가 비면 0을 내는 PromQL 패턴이에요. `or`는 왼쪽에 없는 레이블 조합만 오른쪽에서 가져와요. Grafana 알림 문서도 이 방법을 소개해요.

  하지만 수집이 멈춰도 0이 나와서, 값이 왜 없는지를 지워요. 쓴다면 값이 끊긴 걸 알리는 `absent_over_time()` 알림을 함께 둬요.

  `sum by (route) (...)`처럼 레이블이 남는 결과에 붙이면, 레이블 없는 0 시계열이 하나 더 붙어요. 왼쪽이 빌 때만 0을 붙이려면 `or on() vector(0)`로 써요.

  JavaScript의 `??`는 null과 undefined만 바꾸고, `||`는 0, NaN, 빈 문자열처럼 거짓으로 치는 값을 모두 바꿔요. `?? 0`은 NaN을 그대로 둬서, 그냥 찍으면 화면에 NaN이 떠요. `Number(null)`이나 `null * 100`도 0이라, null로 둔 값도 계산을 거치면 0이 돼요.

  계측 코드에서 미리 내보낸 0은 달라요. 앱이 실제로 내보내는 시계열이라, 수집이 멈추면 다른 시계열과 함께 비어요. 미리 내보내려면 Python 클라이언트에선 `c.labels('get', '/')`처럼 레이블 값만 넣어 한 번 불러 둬요.

  ### 화면과 알림 설정

  Grafana의 Prometheus 데이터 소스는 <Term slug="foundations/aggregation-and-downsampling">점 간격</Term>(step)을 함께 넘겨요. 시계열 패널은 이보다 긴 빈 구간에 null을 넣고, Connect null values 기본값(Never)대로 선을 끊어요.

  대시보드의 Prometheus 질의는 기본이 범위 질의(시간 범위 전체를 점 간격마다 계산하는 질의)예요. Stat 패널의 기본 계산 Last *는 그 범위에서 null과 NaN이 아닌 마지막 값을 골라요. 그래서 No data는 시간 범위 전체에 값이 없을 때만 떠요.

  지금 값을 보려면 질의 옵션의 Type을 Instant로 바꿔요. 시간 범위 끝 시각에 한 번만 계산해서, 그때 값이 없으면 No data가 떠요.

  패널 설정의 No value(값이 비었을 때 대신 보여 줄 글자)를 채우면 No data 대신 그 글자가 떠요. 숫자를 넣으면 시계열 패널은 빈 구간도 그 숫자로 채워서, 0을 넣으면 `?? 0`과 같아요.

  NaN을 '요청 없음'처럼 보이려면 계산을 Last로 바꾸고, Value mappings의 Special로 NaN을 매핑해요. Last *는 NaN을 건너뛰어서 매핑이 걸리지 않아요.

  Grafana 알림은 질의가 성공했는데 데이터가 하나도 없으면 기본으로 No Data 상태가 돼요. 이 처리는 Alerting, Normal, Keep Last State로 바꿀 수 있어요.

  일부 시계열만 사라지면 No Data가 아니에요. 기본 2번 평가 동안 계속 없으면 그 알림은 Normal(MissingSeries)로 해제되고, 해제 알림도 나가요. 횟수는 Missing series evaluations to resolve로 바꿔요.

  Prometheus의 `absent()`는 지금 값이 없을 때, `absent_over_time()`은 구간 내내 없을 때 1을 내요. 둘 다 고른 시계열이 모두 없어야 1을 내서, 여럿 중 하나만 빠진 건 못 잡아요.
</Deeper>
