## 페이지가 뜨는 구간

1. **주소 찾기**: 브라우저가 <Term term="network/dns">DNS</Term>에 도메인 이름을 물어 서버의 IP 주소를 알아내요.
2. **연결**: TCP 3방향 핸드셰이크로 연결을 맺고, HTTPS라면 TLS로 암호화 방식을 정하고 서버를 확인해요.
3. **요청과 첫 바이트**: 요청을 보내고 응답의 첫 바이트를 받기까지예요. 이 시간을 <Term term="apm/ttfb">TTFB</Term>라고 불러요. 서버가 일한 시간과 네트워크 왕복이 함께 들어 있어요.
4. **HTML 해석**: 받은 HTML을 읽어 페이지 구조(DOM)를 만들어요. 중간에 `async`나 `defer`가 없는 `<script>`를 만나면 해석을 멈추고 그 스크립트부터 받아 실행해요.
5. **그리기**: CSS까지 읽은 뒤 화면을 그려요. 이미지처럼 늦게 오는 콘텐츠는 나중에 채워져요.

APM이 재는 서버 응답시간은 3번의 일부일 뿐이에요. 사용자가 기다린 시간은 1번부터 5번까지 전부예요.

## 브라우저가 찍어 두는 시각

브라우저는 페이지를 받는 동안 구간마다 시각을 찍어 두고, 자바스크립트로 읽을 수 있게 해 줘요. 이 기능을 Navigation Timing이라고 불러요.

| 시각 | 뜻 |
| --- | --- |
| domainLookupStart | 도메인 이름 찾기를 시작하기 직전 |
| connectStart | 서버와 연결을 맺기 시작하기 직전 |
| requestStart | 서버에 요청을 보내기 시작하기 직전 |
| responseStart | 응답의 첫 바이트를 받은 직후 |
| responseEnd | 응답의 마지막 바이트를 받은 직후 |
| domContentLoadedEventEnd | DOMContentLoaded 처리가 끝난 직후 |
| loadEventEnd | load 처리가 끝난 직후 |

<Term term="apm/rum">RUM</Term>(실제 사용자 모니터링)은 사용자의 브라우저에서 이 시각들을 읽어 서버로 보내요. 그래서 실제 사용자의 네트워크와 기기에서 걸린 시간을 볼 수 있어요.

## 사용자가 느끼는 세 숫자

구간 시각만으로는 사용자가 언제 "다 떴다"고 느끼는지 알기 어려워요. 그래서 Google은 사용자 체감에 가까운 세 숫자를 <Term term="apm/core-web-vitals">Core Web Vitals</Term>로 묶었어요.

| 숫자 | 재는 것 | 좋음 기준 |
| --- | --- | --- |
| LCP | 가장 큰 콘텐츠가 그려지기까지 | 2.5초 이하 |
| INP | 누르거나 입력한 뒤 다음 화면 반응까지 | 200ms 이하 |
| CLS | 화면이 예고 없이 밀린 정도 | 0.1 이하 |

web.dev는 이 기준을 페이지 로딩의 75번째 백분위수로 보라고 권해요. 모바일과 데스크톱도 나눠서 봐요. 백분위수를 읽는 법은 <Term slug="foundations/percentiles">평균과 백분위수</Term>에 있어요.

## RUM과 외부 감시

같은 페이지 속도라도 재는 방법에 따라 숫자가 달라요. 실제 사용자 브라우저에서 모은 값을 필드 데이터(RUM), 정해 둔 환경에서 페이지를 열어 잰 값을 랩 데이터라고 불러요.

정해 둔 곳에서 주기적으로 주소를 열어 보는 외부 감시(URL 모니터링)는 랩 데이터에 가까워요. 조건이 같아서 변화를 비교하기 좋지만, 실제 사용자의 느린 휴대폰이나 먼 지역은 보여 주지 않아요.

<Deeper>
  ### 렌더링을 막는 스크립트

  MDN은 CSS 파일을 만나도 HTML 해석은 이어진다고 해요. 반면 `async`나 `defer`가 없는 `<script>`는 렌더링을 막고 HTML 해석을 멈춰요. 그래서 페이지 위쪽의 큰 스크립트 하나가 화면 전체를 늦출 수 있어요.

  ### 첫 바이트의 뜻

  `responseStart`는 서버에서 응답의 첫 바이트를 받은 직후예요. MDN은 이 바이트가 최종 응답이 아니라 중간 응답일 수도 있다고 적어요.

  ### 랩과 필드가 다른 이유

  web.dev는 랩 데이터가 일부러 변수를 줄인 환경에서 잰 값이라 필드 데이터와 다를 수 있다고 해요. 실제 사용자는 기기, 네트워크, 캐시 상태가 저마다 달라요.
</Deeper>
