## 만족은 1, 허용은 0.5로 세요

Apdex(Application Performance Index)는 응답시간을 만족도 점수로 바꾸는 공개 표준이에요. 목표 시간 T 이하면 만족, T 초과 4T 이하면 허용, 4T를 넘으면 불만이에요. 점수는 (만족 + 허용 ÷ 2) ÷ 전체 요청 수예요.

그림이라면 (800 + 100 ÷ 2) ÷ 1,000 = 0.85예요. 모두 만족이면 1, 모두 불만이면 0이에요. New Relic과 Datadog은 에러가 난 요청을 빨리 끝났어도 불만으로 세요.

## 점수는 T와 함께 읽어요

같은 요청이라도 T를 바꾸면 점수가 달라져요. 그래서 Apdex 명세는 점수 옆에 T를 `0.85 [0.5]`처럼 함께 쓰라고 해요. T는 도구를 쓰는 사람이 정해요.

기본값도 도구마다 달라요. 명세는 4초를 권하고, New Relic의 앱 서버 기본값은 0.5초예요. 그래서 T가 다른 두 서비스의 점수는 견줄 수 없어요.

## Apdex는 얼마나 느린지를 지워요

4T를 넘은 요청은 3초든 30초든 같은 불만 한 건이에요. 그래서 느린 요청이 더 느려져도 점수는 그대로일 수 있어요. 얼마나 느린지는 <Term slug="foundations/percentiles">p99</Term>와 함께 봐요.

<Deeper>
  ### 명세가 정한 것

  Apdex 명세 1.1(2007년, Apdex Alliance)은 만족을 0~T, 허용을 T 초과~F, 불만을 F 초과로 정해요. F는 T의 네 배예요. T는 초 단위이고, 유효숫자 두 자리까지 써요.

  지금의 Apdex 공식 사이트는 새 쓰임에 맞춰 T와 F의 관계를 유연하게 정한다고 해요. 그래서 4T가 아닌 F를 쓰는 도구가 있다면 설정을 확인해요.

  점수는 소수 둘째 자리까지 쓰고, 0.995 이상은 1.00으로 써요. T는 `0.85 [0.5]`처럼 대괄호로 붙여요. 표본이 1~99개면 `0.85 [0.5]*`처럼 *를 붙이고, 표본이 없으면 NS(No Sample)로 써요.

  명세는 선택 기능으로 등급 이름도 정해요. 0.94 이상은 Excellent, 0.85 이상은 Good, 0.70 이상은 Fair예요. 0.50 이상은 Poor, 그 아래는 Unacceptable이에요.

  ### 에러와 중단

  사용자가 응답 전에 새 요청을 보내 중단하면, 그때까지 걸린 시간으로 구간을 정해요. 서버가 연결을 끊었다면 시간과 상관없이 불만이에요. 도구가 앱 에러(예: 웹 페이지 404 응답)를 알아챌 수 있으면 그것도 불만으로 세요.

  New Relic은 예상된 에러(expected error)로 지정한 에러를 에러율과 Apdex에서 빼요. 요청이 분당 100건보다 적으면 점수가 안정되지 않는다고도 해요.

  ### Prometheus 히스토그램으로 계산하기

  Prometheus 문서는 버킷 두 개로 Apdex를 구하는 질의를 보여 줘요. OpenTelemetry 권장 경계를 쓴다면, T를 0.25초로 잡으면 T와 4T(1초)가 모두 경계예요.

  ```text
  # order-api의 Apdex (T 0.25초, 4T 1초, 에러는 만족·허용에서 뺌)
  (
      sum(rate(http_server_request_duration_seconds_bucket{job="order-api", le="0.25", error_type=""}[5m]))
    +
      sum(rate(http_server_request_duration_seconds_bucket{job="order-api", le="1.0", error_type=""}[5m]))
  ) / 2
    / sum(rate(http_server_request_duration_seconds_count{job="order-api"}[5m]))
  ```

  `le="0.25"`는 만족한 요청 수, `le="1.0"`은 만족과 허용을 더한 수예요. 둘을 더해 2로 나누면 만족 + 허용 ÷ 2예요. `error_type`은 OpenTelemetry가 실패한 요청에만 붙이는 레이블이라, `error_type=""`은 성공한 요청만 골라요.

  Prometheus 3은 정수 경계를 `1.0`처럼 저장해서, `le="1"`로 쓰면 빈 결과예요.
</Deeper>
