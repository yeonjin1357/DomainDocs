<KeyPoints>
  <Point title="선은 부른 쪽과 받은 쪽 span의 짝이에요">
    서비스 맵은 서비스를 노드(점)로, 서비스 사이 호출을 선으로 그린 그림이에요. 트레이스에서 부른 쪽의 CLIENT <Term slug="foundations/logs-metrics-traces">span</Term>과 받은 쪽의 SERVER span이 부모·자식으로 이어진 짝을 찾아 선을 그어요.

    선마다 요청 수, 실패 수, 응답시간을 모아요. 그래서 어느 호출에서 에러가 나는지 선 하나로 보여요.
  </Point>
  <Point title="계측 안 된 곳은 부른 쪽 정보로 그려요">
    DB나 바깥 결제사처럼 span을 보내지 않는 곳은 받은 쪽 span이 없어요. 이때 부른 쪽 span의 `peer.service`나 `db.system` 같은 속성으로 가상 노드를 만들어요. 그런 속성도 없으면 맵에 나오지 않아요.

    반대로 부른 쪽이 계측되지 않았다면, Tempo와 OpenTelemetry Collector는 부른 쪽을 `user`라는 노드로 그려요.
  </Point>
  <Point title="선의 응답시간은 양쪽에서 따로 재요">
    같은 호출을 부른 쪽은 CLIENT span으로, 받은 쪽은 SERVER span으로 재요. 부른 쪽 시간에는 네트워크와 받은 쪽 앞단의 대기가 더해져요. 부른 쪽이 300ms, 받은 쪽이 50ms라면 250ms는 그 사이에서 썼어요.
  </Point>
</KeyPoints>

<Checkpoints>
  <Check>맵에 있어야 할 서비스나 선이 없다면, 그 서비스가 계측됐는지와 `traceparent` 헤더가 넘어가는지 보세요. Elastic은 둘 중 하나라도 안 되면 선을 그리지 못한다고 해요.</Check>
  <Check>계측된 서비스가 부르는 내부 서비스가 `user`에게 불린 것으로 나온다면 <Term slug="apm/broken-traces">트레이스가 끊긴</Term> 거예요. 부른 쪽 span과 이어지지 못해, 받은 쪽에서 새 트레이스가 시작됐어요.</Check>
  <Check>선은 고른 기간에 실제로 호출이 있었을 때만 그려져요. 하루 한 번 도는 배치만 부르는 서비스는 최근 15분 맵에서 빠져요.</Check>
  <Check>샘플링한 트레이스로 만든 맵이라면 요청 수가 실제보다 적어요. Tempo는 이때 요청 수가 실제 트래픽보다 적게 나온다고 하고, <Term slug="apm/sampling">샘플링 비율</Term>을 곱하는 설정을 둬요.</Check>
</Checkpoints>

<Deeper>
  ### 짝을 짓는 방법

  OpenTelemetry Collector의 service graph connector는 Tempo의 같은 기능을 바탕으로 만들었어요. CLIENT와 SERVER, 메시지를 보내는 PRODUCER와 받는 CONSUMER를 짝지어요. DB 호출은 `db.name` 같은 DB 속성이 있는 CLIENT span으로 알아봐요.

  짝이 될 span은 메모리 저장소에 두고, 짝이 오거나 최대 대기 시간이 지나면 기록해요. Collector의 대기 시간(`store.ttl`) 기본값은 2초예요. 짝을 못 찾은 span은 `traces_service_graph_unpaired_spans_total`로 세요.

  한 트레이스의 span이 Collector 여러 대에 흩어지면 짝을 제대로 짓지 못해요. 그래서 앞에 load balancing exporter를 두고, trace id로 같은 인스턴스에 보내요.

  ### 선마다 남는 지표

  선마다 `client`(부른 쪽)·`server`(받은 쪽) 레이블을 붙여 요청 수와 실패 수를 세요. 지표 이름은 `traces_service_graph_request_total`과 `…_request_failed_total`이에요. 응답시간은 부른 쪽(`…_request_client`)과 받은 쪽(`…_request_server`) 히스토그램으로 따로 남겨요.

  ```text
  # 선(부른 쪽 → 받은 쪽)마다 에러율
  sum by (client, server) (
    rate(traces_service_graph_request_failed_total[5m])
  )
    / sum by (client, server) (
      rate(traces_service_graph_request_total[5m])
    )
  ```

  실패 수 지표가 아직 없는 선은 이 결과에 나오지 않아요. 에러율 0인 선까지 보려면 요청 수 쪽 선 목록과 함께 봐요.

  ### 가상 노드의 이름

  Tempo는 가상 노드 이름을 `peer.service`, `db.name`, `db.system`, `db.system.name` 순서로 찾아요. 처음 찾은 값이 이름이 돼요.

  부른 쪽이 없는 root span이 SERVER나 CONSUMER면 부른 쪽을 `user`로 그려요. 스케줄러, 프런트엔드, curl로 보낸 요청이 그 예예요. Tempo는 받은 쪽 span에 peer 속성이 있으면 그 값을 먼저 쓰고, Collector는 늘 `user`로 써요.

  샘플링을 보정하려면 샘플 비율이 든 속성을 `span_multiplier_key`로 정해요. 비율이 0.1이면 span 하나를 요청 10건으로 세요.
</Deeper>
