## 덤프에는 무엇이 있나요

<Term term="apm/thread-dump">스레드 덤프</Term>는 JVM 안의 모든 스레드를 한순간에 찍어, 스레드마다 이름, 상태, <Term term="apm/stack-trace">스택 트레이스</Term>를 적어 줘요. 아래는 그중 스레드 하나의 예시예요.

```text
"http-nio-8080-exec-12" #45
daemon prio=5
  java.lang.Thread.State:
  BLOCKED (on object monitor)
  at com.example.OrderService
   .reserve(OrderService.java:88)
  - waiting to lock
    <0x000000076b1c2a10>
  at com.example.OrderController
    .create(OrderController.java:41)
```

줄이 길어서 나눠 적었어요. 맨 위는 스레드 이름이고, `java.lang.Thread.State` 뒤가 상태예요. 그 아래 `at`으로 시작하는 줄이 스택이에요.

스택은 위로 갈수록 지금 실행 중인 곳이라, 이 스레드는 `OrderService.reserve`의 88번째 줄에서 잠금을 기다리고 있어요.

<Figure caption="위 덤프의 스택을 그렸어요. 아래 메서드가 위 메서드를 불렀고, 맨 위가 지금 멈춰 있는 곳이에요.">
  <TdStack aria-label="BLOCKED 상태인 http-nio-8080-exec-12 스레드의 스택. 맨 위 OrderService.reserve 88번째 줄에서 지금 잠금을 기다리고, 그 아래 OrderController.create 41번째 줄이 reserve를 부른 곳인 그림" />
</Figure>

실행 중인 JVM에서는 `jcmd <PID> Thread.print`로 덤프를 떠요.

## 스레드 상태

| 상태 | 뜻 |
| --- | --- |
| RUNNABLE | JVM 안에서 실행 중이에요. 운영체제의 자원(CPU 등)을 기다릴 수도 있어요 |
| BLOCKED | `synchronized` 잠금을 얻으려고 기다려요 |
| WAITING | 다른 스레드가 무언가 해 주길 기한 없이 기다려요 |
| TIMED_WAITING | 정한 시간까지만 기다려요(`sleep` 등) |

## RUNNABLE의 함정

자바 문서는 RUNNABLE 스레드가 JVM 안에서 실행 중이지만, 운영체제의 자원을 기다리고 있을 수 있다고 해요. 그래서 DB나 외부 API의 응답을 소켓에서 읽으며 기다리는 스레드도 RUNNABLE로 보여요.

RUNNABLE이 많다고 CPU가 바쁘다고 읽으면 안 돼요. 스택 맨 위가 소켓 읽기라면, 그 스레드는 상대의 응답을 기다리는 중이에요.

## 쉬는 스레드도 WAITING이에요

스레드 풀의 쉬는 스레드는 새 일이 오기를 기다리며 WAITING이나 TIMED_WAITING으로 보여요. 그래서 WAITING이 많다는 것만으로는 문제가 아니에요. 문제는 요청을 처리하던 스레드가 무언가에 막혀 기다릴 때예요.

## CPU를 쓰는 스레드 찾기

덤프의 스택만 봐서는 RUNNABLE 가운데 누가 정말 CPU를 쓰는지 알 수 없어요. 운영체제가 보는 스레드별 CPU와 덤프를 이어야 해요.

리눅스에서 `top -H -p <PID>`를 쓰면 그 프로세스의 스레드마다 CPU 사용률이 나와요. 맨 앞 PID 칸이 스레드 번호예요. 자바는 스레드 이름 앞 15자를 운영체제에도 알려 줘서, 맨 끝 칸에 이름 앞부분이 보여요.

```text
  PID  S  %CPU  COMMAND
  612  R  99.9  busy-wo+
  586  S   0.0  java
```

이 번호를 덤프에서 찾으면 그 스레드의 스택이 나와요. 그런데 덤프가 번호를 적는 방식이 JDK 버전마다 달라요.

<Figure caption="JDK 11·17·21·25에서 같은 실험을 한 결과예요. top -H의 스레드 번호를 JDK 17까지는 16진수로 바꿔 찾고, JDK 21부터는 그대로 찾아요. 숫자는 JDK 21 실험의 612로 맞췄어요.">
  <TdJdk aria-label="top -H에서 CPU를 많이 쓰는 스레드 번호 612를 찾으면, JDK 11·17에서는 16진수 264로 바꿔 덤프에서 nid=0x264를 찾고, JDK 21·25에서는 그대로 nid=612나 [612]를 찾는 그림" />
</Figure>

16진수는 `printf '%x
' 612`로 바꿔요. 아래는 JDK 21로 뜬 덤프에서 그 스레드를 찾은 모습이에요.

```text
"busy-worker" #28 [612] daemon
 cpu=6249.82ms elapsed=6.26s
 nid=612 runnable
 java.lang.Thread.State: RUNNABLE
 at Busy.lambda$main$0(Busy.java:8)
```

덤프 줄의 `cpu=`는 그 스레드가 지금까지 쓴 CPU 시간이에요. 확인한 JDK 11부터 25까지 모두 이 칸이 있었어요. 몇 초 간격으로 두 번 떠서 이 값이 크게 는 스레드가, 지금 CPU를 쓰는 스레드예요.

<Deeper>
  ### 상태의 정확한 뜻

  BLOCKED는 모니터 잠금을 기다리는 상태예요. `synchronized` 블록에 들어가거나, `Object.wait` 뒤에 다시 들어가려고 기다려요. WAITING은 기한 없는 `Object.wait`, `Thread.join`, `LockSupport.park`를 부른 상태예요.

  TIMED_WAITING은 `Thread.sleep`처럼 기다릴 시간을 정해 부른 상태예요. 스레드 풀의 쉬는 스레드는 보통 `LockSupport.park` 계열로 일을 기다려서 WAITING이나 TIMED_WAITING으로 보여요.

  ### 덤프의 부담

  jcmd 문서는 `Thread.print`의 부담(Impact)을 "중간, 스레드 수에 따라 달라짐"으로 적어요. 스레드가 수천 개인 JVM이라면 덤프 한 번에도 시간이 걸려요.
</Deeper>
