그림을 따라 쿼리 하나를 보내 볼게요. 쿼리는 DB에 보내는 SQL 한 문장이에요.

1. **연결·세션**: 앱이 DB에 <Term term="database/connection">연결</Term>을 맺어요. DB는 이 접속의 <Term term="database/session">세션</Term>을 만들고, 일을 맡을 프로세스나 스레드를 붙여요.
2. **해석**: <Term term="database/parser">파서</Term>가 문법이 맞는지, 테이블과 열이 정말 있는지 확인해요.
3. **계획**: <Term term="database/optimizer">옵티마이저</Term>가 데이터를 가져올 여러 방법 중 가장 싸 보이는 <Term term="database/execution-plan">실행 계획</Term>을 골라요.
4. **실행**: 계획대로 데이터를 읽어요. 필요한 <Term term="database/block">블록</Term>이 <Term term="database/buffer-cache">버퍼 캐시</Term>에 있으면 메모리에서 읽고, 없으면 디스크에서 가져와요.
5. **기록**: 데이터를 바꾸는 쿼리라면, 바뀐 내용을 <Term term="database/wal">로그</Term>에 먼저 적어요. 커밋할 때 데이터 파일까지 바로 쓰지 않아도 돼요.
6. **결과**: 모은 행을 같은 연결로 앱에 돌려줘요.

로그에 먼저 적는 이유는 장애에 대비하기 위해서예요. 데이터 파일에 미처 쓰지 못한 변경이 있어도, 다시 켤 때 로그를 보고 되살려요.

## 단계를 하나씩 확대해 봐요

기초 글은 그림의 칸 하나를 확대해서 설명해요.

- 1단계(연결·세션)는 <Term slug="database/connections-and-sessions">연결과 세션</Term>에서 다뤄요.
- 2~4단계(해석·계획·실행)는 <Term slug="database/query-processing">SQL이 실행되는 과정</Term>에서 다뤄요.
- 계획이 고르는 빠른 길은 <Term slug="database/indexes">인덱스</Term>에서 다뤄요.
- 큰 표를 기준 열로 나눠 담는 법은 <Term slug="database/partitioning">테이블 파티셔닝</Term>에서 다뤄요.
- 4단계의 블록과 버퍼 캐시는 <Term slug="database/memory-and-disk">메모리와 디스크</Term>에서 다뤄요.
- 데이터 파일과 언두·임시 공간은 <Term slug="database/tablespaces">테이블스페이스와 언두·임시 공간</Term>에서 다뤄요.
- 5단계의 기록과 커밋은 <Term slug="database/transactions">트랜잭션과 커밋</Term>에서 다뤄요.
- 로그가 장애 뒤 데이터를 되살리는 법은 <Term slug="database/logs-and-recovery">로그와 복구</Term>에서 다뤄요.
- 여러 세션이 같은 데이터를 함께 다루는 법은 <Term slug="database/concurrency">동시에 읽고 쓰기</Term>에서 다뤄요.
- 로그를 다른 서버로 보내 사본을 두는 법은 <Term slug="database/replication">복제</Term>에서 다뤄요.

관계형 DB와 다르게 저장하는 DB도 있어요. 쿼리가 지나가는 길이 위 그림과 달라서 따로 다뤄요.

- 표 대신 키나 문서로 저장하는 DB는 <Term slug="database/nosql">관계형이 아닌 DB(NoSQL)</Term>에서 다뤄요.
- 데이터를 메모리에 두는 저장소는 <Term slug="database/in-memory-store">인메모리 저장소(Redis)</Term>에서 다뤄요.
- 분석용으로 열마다 모아 저장하는 DB는 <Term slug="database/columnar">열 지향 DB와 데이터 웨어하우스</Term>에서 다뤄요.

## 단계마다 모니터링 화면이 있어요

DB 모니터링 화면은 대부분 이 길의 한 칸을 들여다봐요. 기초를 읽은 뒤 이어 보면 화면의 숫자가 어디서 오는지 보여요.

- 연결·세션: 지금 일하는 세션과 기다리는 대상은 <Term slug="database/active-sessions">액티브 세션과 대기 이벤트</Term>에서 봐요.
- 해석·계획: 계획이 실제로 어떻게 돌았는지는 <Term slug="database/execution-plans">실행 계획 읽기</Term>에서 봐요.
- 실행: 어떤 SQL이 DB 시간을 가장 많이 쓰는지는 <Term slug="database/top-sql">SQL별 부하 순위</Term>에서 봐요.
- 버퍼 캐시: 메모리에서 찾은 비율의 함정은 <Term slug="database/buffer-cache-hit-ratio">버퍼 캐시 적중률</Term>에서 봐요.
- 로그: 로그를 다른 서버로 보내 따라오게 하는 복제는 <Term slug="database/replication-lag">복제 지연</Term>에서 봐요.
- DB 종류: 같은 정보를 DB마다 어디서 읽는지는 <Term slug="database/db-names">DB마다 다른 이름</Term>에 모았어요.
