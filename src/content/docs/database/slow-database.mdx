## 1. 정말 DB 안에서 느린지 보세요

앱이 잰 DB 구간에는 커넥션을 얻기까지의 대기와 네트워크 시간도 섞여요. 앱의 <Term slug="apm/connection-pool">커넥션 풀</Term> 대기가 늘었다면, DB보다 앱 쪽 풀이 먼저예요.

DB가 잰 SQL 실행 시간이 그대로라면 문제는 DB 밖에 있어요. DB가 잰 시간까지 늘었다면 다음 단계로 가요.

## 2. 액티브 세션을 대기 종류로 나눠 보세요

<Term slug="database/active-sessions">액티브 세션</Term>이 평소보다 늘었는지, 늘어난 몫이 무엇을 기다리는지 봐요. 대기 종류가 다음 단계를 정해요.

<Figure caption="늘어난 액티브 세션이 무엇을 기다리는지가 다음 단계를 정해요.">
  <Flow

      { id: 'lock', label: 'Lock', col: 0, row: 1, note: '4단계: 막는 쪽' },
      { id: 'work', label: 'IO·CPU', col: 1, row: 1, note: '3단계: SQL' },

- **Lock이 늘었다면**: 서로의 잠금을 기다려요. 4단계로 가요.
- **IO나 CPU가 늘었다면**: 일 자체가 늘었거나 무거워졌어요. 3단계로 가요.
- **늘어난 게 없다면**: DB는 한가해요. 1단계로 돌아가 DB 밖을 봐요.

**확인 방법**: 아래 질의를 장애 시각에 몇 번 돌리거나, 모니터링 도구의 액티브 세션 그래프를 대기 종류별로 봐요.

```text
-- 지금 액티브 세션을 기다리는 대상별로 세기
SELECT coalesce(wait_event_type, 'CPU') AS waiting_for, count(*)
FROM pg_stat_activity
WHERE state = 'active' AND backend_type = 'client backend'
GROUP BY 1;
```

## 3. 그 시각에 늘어난 SQL을 찾으세요

장애 구간의 <Term slug="database/top-sql">SQL별 실행 시간 합</Term>을 평소와 견줘, 가장 많이 늘어난 SQL을 찾아요. 그다음 호출 수가 늘었는지, 평균 시간이 늘었는지 갈라요.

호출 수가 늘었다면 앱 쪽 변화부터 봐요. 배포로 같은 SQL을 더 자주 부르거나, 캐시가 만료돼 DB로 몰렸을 수 있어요. 평균 시간이 늘었다면 그 SQL을 <Term slug="database/execution-plans">EXPLAIN ANALYZE</Term>로 열어 예상과 실제 행 수를 견줘요.

**확인 방법**: `pg_stat_statements`의 값은 누적값이에요. 장애 직전과 지금 두 번 떠서, SQL마다 `calls`와 `total_exec_time`의 차이를 구해요.

## 4. Lock 대기라면 막고 있는 세션을 찾으세요

<Term slug="database/locks-and-blocking">Lock</Term>을 기다리는 세션마다 누가 막고 있는지 찾아요. `pg_blocking_pids(pid)`는 그 세션을 막고 있는 세션들의 pid를 돌려줘요.

```text
-- 막힌 세션과, 막고 있는 세션의 pid
SELECT pid, pg_blocking_pids(pid) AS blocked_by, wait_event, query
FROM pg_stat_activity
WHERE cardinality(pg_blocking_pids(pid)) > 0;
```

막고 있는 세션의 `state`가 `idle in transaction`이라면, 앱이 트랜잭션을 연 채 다른 일을 하고 있어요. 잠금은 보통 트랜잭션이 끝날 때까지 남아서, 그동안 뒤의 세션이 모두 줄을 서요.

**확인 방법**: 막고 있는 pid로 `pg_stat_activity`를 다시 조회해요. `state`, `xact_start`(트랜잭션 시작 시각), `query`를 봐요.

급하면 `pg_terminate_backend(pid)`로 그 세션을 끝낼 수 있어요. 그 세션의 트랜잭션은 커밋되지 않고 사라지니, 앱 쪽 원인을 함께 고쳐요. 쿼리만 멈출지 세션째 끊을지는 <Term slug="database/stop-long-query">오래 도는 쿼리 멈추기</Term>에서 다뤄요.
