## 설정값은 무엇인가요

<Term term="database/db-parameter">설정값</Term>(파라미터)은 DB가 어떻게 움직일지 정하는 이름과 값의 쌍이에요. 연결을 몇 개까지 받을지, 공유 메모리를 얼마나 잡을지, 정렬에 메모리를 얼마나 쓸지 같은 것들이에요.

DB마다 설정값이 수백 개 있어요. 대부분은 기본값 그대로 두고, 서비스에 맞춰 몇십 개를 고쳐 써요.

`ALTER SYSTEM`은 SQL로 설정 파일을 고치는 명령이에요. 실행해도 파일만 바뀌고, 지금 쓰는 값은 그대로예요. DB가 파일을 다시 읽어야 쓰여요.

## 바로, 다시 읽기, 다시 시작

설정마다 언제 쓰이기 시작하는지가 정해져 있어요. PostgreSQL은 이걸 `pg_settings`의 `context`로 알려 줘요.

- **세션에서 바로**(`user` 등): `work_mem`처럼 세션에서 `SET`으로 바로 바꿀 수 있어요.
- **다시 읽기**(`sighup`): `checkpoint_timeout`처럼 파일을 고치고 <Term term="database/config-reload">다시 읽기</Term>(reload)를 하면 쓰여요.
- **다시 시작**(`postmaster`): `shared_buffers`, `max_connections`처럼 DB를 다시 시작해야 쓰여요.

<Figure caption="PostgreSQL 18에서 체크포인트 간격(checkpoint_timeout)과 공유 버퍼(shared_buffers)를 함께 고친 결과예요. 앞의 것은 다시 읽기 뒤 바로 바뀌었지만, 뒤의 것은 다시 시작할 때까지 옛 값이에요.">

다시 읽기를 해도 바뀌지 않은 설정은 `pending_restart`가 true로 바뀌어요. 다시 시작해야 쓰일 값이 남아 있다는 표시예요.

```sql
SELECT name, setting
FROM pg_settings
WHERE pending_restart;
```

## DB마다 같은 구조예요

이름은 달라도 다른 DB도 같은 구조예요. 설정값이 지금 쓰는 값(메모리)과 다음 시작 때 읽을 값(파일) 두 곳에 있어요. 바꾸는 명령마다 어느 쪽을 고치는지가 달라요.

<Figure caption="MySQL의 SET과 Oracle의 SCOPE는 같은 세 갈래예요. 지금 값만 바꾸면 다시 시작할 때 사라지고, 파일만 바꾸면 다시 시작해야 쓰여요.">
  <Compare

    rows={[
      { label: 'MySQL SET GLOBAL · Oracle SCOPE=MEMORY', values: ['바뀌어요', '옛 값으로 돌아가요'] },
      { label: 'MySQL SET PERSIST · Oracle SCOPE=BOTH', values: ['바뀌어요', '바뀐 값이에요'] },
      { label: 'MySQL SET PERSIST_ONLY · Oracle SCOPE=SPFILE', values: ['그대로예요', '바뀐 값이에요'] },
    ]}
  />
</Figure>

지금 쓰는 값은 DB마다 다른 곳에서 확인해요.

- **PostgreSQL**: `pg_settings`의 `setting`이 지금 값이에요. `pending_restart`로 다시 시작이 필요한지 봐요.
- **MySQL**: `SHOW GLOBAL VARIABLES`가 지금 값이에요. `SET PERSIST`로 남긴 값은 `mysqld-auto.cnf`에 있어요.
- **Oracle**: `V$PARAMETER`가 지금 값이에요. `ISSYS_MODIFIABLE`이 언제 쓰이는지 알려 줘요.
- **SQL Server**: `sys.configurations`의 `value`는 적은 값, `value_in_use`는 지금 쓰는 값이에요. `sp_configure`로 고친 뒤 `RECONFIGURE`를 해야 쓰여요.

<Deeper>
  ### PostgreSQL의 context 종류

  `context`는 일곱 가지예요. 가장 바꾸기 어려운 internal은 빌드나 설치 때 정해져서 바꿀 수 없어요. 그다음이 postmaster, sighup, superuser-backend, backend 순서예요.

  superuser는 슈퍼유저나 권한을 받은 사용자만 세션에서 바꿀 수 있어요. 가장 쉬운 user는 누구나 세션에서 바꿔요.

  `ALTER DATABASE`와 `ALTER ROLE`로 정한 값은 새 세션이 열릴 때만 적용돼요. 이미 열린 세션은 옛 값 그대로예요.

  ### 다시 읽기에서 생기는 일

  다시 읽기를 해도 다시 시작이 필요한 값은 바꾸지 않아요. 대신 서버 로그에 "cannot be changed without restarting the server"를 남겨요. 이미 도는 세션은 하던 명령을 마친 뒤 새 값을 받아요.

  ### MySQL의 동적 변수

  MySQL은 변수마다 Dynamic 여부가 문서에 적혀 있어요. `innodb_buffer_pool_size`도 Dynamic이라 다시 시작하지 않고 바꿀 수 있어요. 다만 크기를 바꾸는 동안 버퍼 풀을 조금씩 옮겨요.

  ### Oracle과 SQL Server

  Oracle의 `ISSYS_MODIFIABLE`은 세 가지예요. IMMEDIATE는 바로, DEFERRED는 다음 세션부터, FALSE는 spfile에 적고 다시 시작해야 쓰여요. SQL Server의 `is_dynamic`이 1이면 RECONFIGURE만으로 쓰이고, 0이면 다시 시작해야 해요.
</Deeper>
