## 데이터는 블록에 담겨요

DB는 테이블과 인덱스를 같은 크기의 조각으로 나눠 디스크에 저장해요. 이 조각을 <Term term="database/block">블록</Term>(또는 페이지)이라고 불러요. 읽고 쓸 때도 블록 하나가 단위예요.

| DB | 부르는 이름 | 기본 크기 |
| --- | --- | --- |
| PostgreSQL | 페이지 | 8KB |
| Oracle | 블록 | 8KB(`DB_BLOCK_SIZE`) |
| MySQL InnoDB | 페이지 | 16KB(`innodb_page_size`) |
| SQL Server | 페이지 | 8KB |

그래서 행 하나만 필요해도 그 행이 든 블록을 통째로 읽어요. 같은 블록에 있는 다른 행도 함께 메모리로 올라와요.

## 버퍼 캐시에서 먼저 찾아요

<Term term="database/buffer-cache">버퍼 캐시</Term>는 디스크에서 읽은 블록을 담아 두는 메모리예요. DB는 블록이 필요하면 먼저 버퍼 캐시를 보고, 없을 때만 디스크에서 읽어 와요.

메모리는 디스크보다 훨씬 빨라서, 자주 쓰는 블록이 캐시에 있으면 쿼리가 빨라져요. 캐시에서 찾는 것을 적중, 못 찾아 디스크를 읽는 것을 실패라고 불러요.

버퍼 캐시는 크기가 정해져 있어요. 자리가 모자라면 오래 안 쓴 블록부터 내보내고 새 블록을 들여요. MySQL InnoDB는 이를 LRU(최근에 가장 덜 쓴 것부터 내보내는 방식)를 고친 규칙으로 해요.

## 바꾼 블록은 나중에 써요

데이터를 바꾸면 DB는 버퍼 캐시의 블록을 고쳐요. 이렇게 메모리에서만 바뀌고 아직 디스크에 쓰지 않은 블록을 <Term term="database/dirty-block">더티 블록</Term>이라고 불러요.

더티 블록을 한꺼번에 디스크에 쓰는 때가 <Term term="database/checkpoint">체크포인트</Term>예요. PostgreSQL은 체크포인트에서 모든 더티 블록을 디스크에 쓰고, 그 지점을 로그에 표시해요.

체크포인트 사이에 장애가 나면 디스크에 못 쓴 변경이 남아요. 이 변경은 먼저 적어 둔 <Term term="database/wal">로그</Term>로 되살려요. 그래서 블록을 매번 바로 쓰지 않아도 돼요.

DB 화면의 디스크 읽기와 쓰기는 이 흐름을 그대로 보여 줘요. 읽기가 늘었다면 버퍼 캐시에서 못 찾은 블록이 늘었다는 뜻이에요. 쓰기가 주기적으로 솟는다면 체크포인트일 수 있어요.

PostgreSQL은 체크포인트 쓰기를 다음 체크포인트 전까지 나눠 써서 봉우리를 낮춰요. 그래도 바꾸는 데이터가 많으면 이 시간에 디스크가 바빠져요.

버퍼 캐시에서 찾은 비율(적중률)도 자주 보는 숫자예요. 다만 높다고 늘 좋은 건 아니에요. 그 함정은 <Term slug="database/buffer-cache-hit-ratio">버퍼 캐시 적중률의 함정</Term>에서 봐요.

  <Check>PostgreSQL의 `shared_buffers`를 메모리 대부분으로 잡자는 제안이라면 다시 보세요. PostgreSQL은 운영체제 캐시에도 기대서, 문서는 전용 서버에서 메모리의 25%쯤부터 시작하라고 해요.</Check>
  <Check>DB를 다시 시작한 직후 느려졌다면 버퍼 캐시가 비어 있는지 보세요. 캐시가 다시 찰 때까지 디스크 읽기가 늘어요.</Check>
</Checkpoints>

<Deeper>
  ### PostgreSQL의 이중 캐시

  PostgreSQL은 자기 버퍼 캐시(`shared_buffers`) 말고도 운영체제의 파일 캐시를 함께 써요. 그래서 버퍼 캐시에서 못 찾았다고 늘 디스크를 읽는 건 아니에요. 운영체제 캐시에서 찾을 수도 있어요.

  `pg_prewarm` 확장은 테이블 데이터를 미리 캐시에 올려 둘 수 있어요. 다시 시작한 뒤 캐시를 채우는 데 쓸 수 있어요.

  ### 블록 크기는 처음에 정해요

  MySQL InnoDB의 페이지 크기는 데이터 디렉터리를 처음 만들 때만 정할 수 있어요. 64KB, 32KB, 16KB, 8KB, 4KB 중 하나예요.

  PostgreSQL의 페이지 크기는 서버를 컴파일할 때 정해요. Oracle은 `DB_BLOCK_SIZE`로 2KB에서 32KB 사이를 고를 수 있어요.

  ### SQL Server의 익스텐트

  SQL Server는 연속된 페이지 8개(64KB)를 익스텐트로 묶어 관리해요. 데이터 파일 읽기와 쓰기는 페이지 단위로 해요.
</Deeper>
