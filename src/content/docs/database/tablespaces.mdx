  </Point>

  </Point>
</KeyPoints>

Oracle 문서는 <Term term="database/tablespace">테이블스페이스</Term>를 '세그먼트를 담는 논리적인 그릇'이라고 해요. 세그먼트는 표나 인덱스 하나가 차지한 공간이에요. 물리적으로는 데이터 파일이나 임시 파일 하나 이상에 저장돼요.

<Term term="database/data-file">데이터 파일</Term>은 자동 확장(`AUTOEXTEND`)을 켜 두면 차는 대로 커져요. 최대 크기(`MAXSIZE`)에 닿거나 디스크가 차면 더 커지지 못해요. 그러면 표에 행을 넣다가 ORA-01653처럼 '테이블스페이스를 늘릴 수 없다'는 에러가 나요.

## 언두: 바꾸기 전 값

Oracle은 행을 바꿀 때 바꾸기 전 값을 <Term term="database/undo">언두</Term> 테이블스페이스에 둬요. 쓰임새는 둘이에요.

- 트랜잭션을 되돌릴 때 옛 값으로 돌려놔요.
- 다른 세션이 바뀌는 중인 행을 읽으면, 언두로 바뀌기 전 모습을 만들어 보여 줘요.

커밋한 뒤의 언두도 한동안 남겨 둬요. 자동 확장하는 언두라면 `UNDO_RETENTION`(기본 900초)을 최소 보관 시간으로 지키려 하고, 모자라면 먼저 파일을 늘려요. 최대 크기에 닿으면 보관 시간이 안 지난 언두도 덮어쓸 수 있어요.

오래 도는 조회가 이미 덮어쓴 옛 값을 찾으면 ORA-01555(snapshot too old)가 나요. 문서는 일관된 읽기에 필요한 언두를 다른 쓰기가 덮어썼다는 뜻으로 설명해요. 그래서 긴 조회와 많은 쓰기가 겹칠 때 잘 나요.

PostgreSQL에는 따로 언두가 없어요. 옛 값을 표 안에 그대로 두고, 나중에 VACUUM이 치워요. 이 차이는 <Term slug="database/concurrency">동시에 읽고 쓰기</Term>에서 다뤄요.

## 임시 공간: 넘친 작업

Oracle 문서는 임시 테이블스페이스에 정렬 중간 결과, 임시 표와 인덱스 같은 것을 둔다고 해요. 세션 동안에만 필요한 데이터예요.

큰 정렬이 여러 개 겹쳐 임시 공간을 다 쓰면 ORA-01652가 나요. Oracle 23의 문구는 'unable to grow … in tablespace …'로, 임시 공간을 더 늘릴 수 없다는 뜻이에요. 넘치는 원리와 줄이는 법은 <Term slug="database/temp-spill">정렬·해시가 디스크로 넘칠 때</Term>에 있어요.

## PostgreSQL의 테이블스페이스

PostgreSQL에서 테이블스페이스는 데이터를 둘 디렉터리 위치일 뿐이에요. 따로 만들지 않으면 기본 `pg_default`와 공용 `pg_global` 둘만 있어요.

그래서 PostgreSQL에서는 테이블스페이스가 차는 일보다, 그 디렉터리가 있는 디스크가 차는 일을 지켜봐요. 임시 파일도 기본으로 같은 디스크에 써요.

자동 확장이 켜진 테이블스페이스는 지금 크기만 보면 늘 가득 차 보여요. `DBA_TABLESPACE_USAGE_METRICS`의 `TABLESPACE_SIZE`는 자동 확장으로 커질 수 있는 최대 크기예요. 이 값 대비 사용률로 봐야 진짜 남은 공간이 보여요.

다만 최대 크기까지 커질 디스크 공간이 실제로 있는지도 함께 봐요. 서버 디스크 보는 법은 <Term slug="server/disk-filling-up">디스크가 차오를 때</Term>와 같아요.

언두와 임시 공간은 순간적으로 차요. 사용률 평균보다 ORA-01555, ORA-01652 같은 에러가 몇 번 났는지 함께 봐요.

<Deeper>
  ### MySQL InnoDB의 언두와 임시 공간

  MySQL InnoDB도 바뀐 행의 옛 정보를 언두 테이블스페이스에 둬요. 정렬이나 그룹화에 쓰는 내부 임시 표가 메모리 한도를 넘으면 디스크로 옮겨요.

  ### 고정 크기 언두의 보관 시간

  고정 크기 언두에서는 `UNDO_RETENTION`을 쓰지 않아요. 대신 DB가 공간과 쓰기 양을 보고, 가장 오래 도는 조회보다 조금 길게 보관 시간을 스스로 맞춰요. 자동 확장 언두에서도 이 자동 조정은 함께 일어나요.
</Deeper>
