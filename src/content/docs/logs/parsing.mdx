  </Point>

## 정규식으로 나누기

아래 같은 텍스트 로그는 <Term term="logs/log-parsing">파싱</Term> 규칙이 있어야 필드로 쓸 수 있어요.

```text
2026-10-29 17:22:19 ERROR [order-api] payment failed order_id=A1042
```

Fluent Bit에서는 파서에 정규식을 적어 나눠요. `(?<이름>…)` 모양의 이름 붙은 묶음이 필드가 돼요.

```ini
[PARSER]
    Name        app
    Format      regex
    Regex       ^(?<time>[^ ]+ [^ ]+) (?<level>\w+) \[(?<service>[^\]]+)\] (?<msg>.*)$
    Time_Key    time
    Time_Format %Y-%m-%d %H:%M:%S
    Time_Offset +0900
```

이 정규식을 Node로 돌려 보니 위 줄이 이렇게 나뉘었어요.

| 필드 | 값 |
| --- | --- |
| time | 2026-10-29 17:22:19 |
| level | ERROR |
| service | order-api |
| msg | payment failed order_id=A1042 |

`Time_Key`는 시각이 든 필드 이름이고, `Time_Format`은 그 시각의 형식이에요. `Time_Offset`은 시간대가 적히지 않은 시각에 붙일 UTC 차이예요.

msg 안의 `order_id=A1042`는 아직 글자 그대로예요. 이런 key=value는 logfmt 해석으로 한 번 더 나눠요.

Loki는 찾을 때 나누는 방식을 많이 써요. `| json`, `| logfmt`, `| pattern`, `| regexp` 같은 파서를 질의에 붙여요.

```text
{app="order-api"}
  |= "payment failed"
  | regexp "order_id=(?P<order_id>\\w+)"
```

Loki 문서는 파서가 줄 필터보다 비싸다고 해요. 그래서 위처럼 `|=` 필터로 먼저 줄을 줄이고, 남은 줄만 파서로 나눠요.

## 시각 읽기

로그에는 시각이 두 개 있을 수 있어요. 줄에 적힌 일이 일어난 시각과, 수집 쪽이 그 줄을 본 시각이에요. 검색 화면은 보통 앞의 시각으로 줄을 세워요.

줄에 적힌 시각에 시간대가 없으면 문제가 생겨요. `2026-10-29 17:22:19`를 Node로 읽어 봤어요.

| 읽는 서버의 시간대 | 저장된 시각(UTC) |
| --- | --- |
| Asia/Seoul | 2026-10-29T08:22:19Z |
| UTC | 2026-10-29T17:22:19Z |

같은 줄이 서버에 따라 9시간 다른 자리에 저장돼요. 그러면 그 로그는 검색 범위를 넓혀야 찾을 수 있어요. 확인 순서는 <Term slug="foundations/logs-missing">로그가 안 들어올 때</Term>에 있어요.

가장 확실한 방법은 앱이 처음부터 `2026-10-29T08:22:19Z`처럼 시간대를 붙여 쓰는 거예요. 고칠 수 없다면 파서에 `Time_Offset` 같은 설정으로 시간대를 정해요.

## 여러 줄 로그

자바 스택 트레이스처럼 한 사건이 여러 줄이면, 파싱보다 먼저 묶어야 해요. 묶지 않으면 둘째 줄부터는 시각도 레벨도 없는 줄이 돼요. 수집 에이전트의 묶는 설정은 <Term slug="foundations/log-collection">로그가 모이는 길</Term>에서 다뤄요.

파싱이 실패하면 필드가 비어요. 레벨 필드로 건 알림은 ERROR가 0이 되니 조용해져요. 오류가 사라진 게 아니라 못 세는 거예요.

위에서 쓴 정규식은 날짜를 `2026/10/29`로 바꾼 줄에 아무것도 맞추지 못했어요. 로그 형식을 바꾸는 배포는 파서와 함께 바꿔야 해요.

그래서 파싱에 실패한 줄 수를 지표로 따로 둬요. 배포 직후 이 값이 뛰면 파서부터 봐요.

<Deeper>
  ### 정규식 문법의 차이

  Fluent Bit 정규식은 Ruby 문법을 써서 이름 붙은 묶음을 `(?<name>…)`로 써요. Loki의 `regexp`는 RE2를 써서 `(?P<name>…)`로 써요. 같은 규칙도 옮길 때 이 부분을 고쳐야 해요.

  ### 원래 시각 필드 남기기

  Fluent Bit은 시각을 읽고 나면 원래 시각 필드를 지워요. `Time_Keep`을 켜면 남겨요. 시각 읽기가 의심될 때 원래 글자를 남겨 두면 견줘 볼 수 있어요.

  ### 재현 조건

  정규식과 시각 해석은 Node 22로 돌렸어요. 시간대 없는 ISO 날짜·시각 글자는 Node가 실행 환경의 지역 시간으로 읽어서, `TZ`를 바꿔 두 번 돌렸어요.
</Deeper>
