<KeyPoints>
  <Point title="모든 단어를 색인하면 찾기가 빨라요">
    Elasticsearch 같은 저장소는 줄을 단어로 쪼개, 단어마다 어느 줄에 있는지 적어 둬요. 대신 색인을 만들고 두는 비용이 커요.
  </Point>
  <Point title="라벨만 색인하면 싸지만 훑어요">
    Loki는 서비스, 환경 같은 라벨만 색인하고 본문은 압축해 둬요. 라벨로 좁힌 뒤 본문을 훑어요.
  </Point>
  <Point title="열로 모으면 집계가 빨라요">
    열 지향 DB에 넣으면 필드마다 모아 압축해서, 레벨별·서비스별로 세는 일이 빨라요.
  </Point>
</KeyPoints>

<Analogy limit="책의 찾아보기는 한 번 만들면 끝이지만, 로그는 초당 수천 줄이 새로 들어와서 색인도 계속 다시 만들어야 해요.">
  두꺼운 책에서 단어를 찾는 방법과 같아요. 책 뒤의 찾아보기를 보면 바로 쪽수가 나와요. 찾아보기가 없으면 장 제목으로 범위를 좁힌 뒤 그 장을 넘겨 봐요.
</Analogy>

## 모든 단어를 색인하기

<Term term="logs/inverted-index">역색인</Term>은 단어마다 그 단어가 든 줄 번호를 적은 표예요. 로그 세 줄로 만들면 이렇게 돼요.

| 줄 | 내용 |
| --- | --- |
| 1 | payment failed order A1042 |
| 2 | payment ok order A1043 |
| 3 | db timeout order A1042 |

| 단어 | 든 줄 |
| --- | --- |
| payment | 1, 2 |
| failed | 1 |
| timeout | 3 |
| A1042 | 1, 3 |

"A1042"를 찾으면 표에서 바로 1번과 3번 줄이 나와요. 줄이 수억 개여도 드문 단어는 금방 찾아요.

Elasticsearch의 text 필드가 이렇게 저장돼요. 글자를 분석기로 단어 목록으로 바꾼 뒤 색인해요. 정확한 값을 찾거나 정렬, 집계할 값은 keyword 필드로 둬요.

대신 들어오는 모든 줄의 모든 단어로 색인을 만들어요. 그래서 넣을 때 일이 많고, 색인이 차지하는 공간도 커요.

## 라벨만 색인하기

Loki는 본문을 색인하지 않고, 로그 스트림마다 붙은 <Term term="logs/log-label">라벨</Term>만 색인해요. 본문은 압축 덩어리(chunk)로 묶어 S3 같은 객체 저장소에 둬요. Loki 문서는 작은 색인과 잘 압축된 덩어리가 비용을 크게 낮춘다고 해요.

찾을 때는 라벨로 스트림을 먼저 고르고, 그 스트림의 덩어리를 풀어 본문을 훑어요. 그래서 라벨로 좁히지 않거나 시간 범위가 넓으면 훑을 양이 많아져요.

라벨에는 값이 몇 가지로 정해진 것만 둬요. 사용자 ID나 요청 ID를 라벨로 만들면, 값마다 스트림이 생겨 색인은 커지고 덩어리는 잘게 쪼개져요. Loki 문서는 이런 값은 라벨 대신 `|= "requestId=…"` 같은 필터로 찾으라고 해요.

## 열로 모아 저장하기

로그를 필드별로 나눠 열 지향 DB에 넣기도 해요. 같은 필드의 값끼리 모여서 잘 압축되고, "레벨별 분당 줄 수" 같은 집계가 빨라요. 원리는 <Term slug="database/columnar">열 지향 DB와 데이터 웨어하우스</Term>에서 다뤄요.

대신 메시지 본문 안의 아무 단어나 찾는 일은 그 열을 훑어야 해요. 그래서 자주 찾는 값은 따로 필드로 빼 두는 게 좋아요.

## 세 방식 한눈에

| | 모든 단어 색인 | 라벨만 색인 | 열로 저장 |
| --- | --- | --- | --- |
| 예 | Elasticsearch, OpenSearch | Loki | 열 지향 DB |
| 빠른 일 | 드문 단어 찾기 | 라벨로 좁힌 최근 로그 | 필드별 집계 |
| 비싼 일 | 색인 만들기와 보관 | 넓은 범위의 본문 훑기 | 본문 아무 단어 찾기 |

저장 방식에 따라 지켜볼 숫자가 달라요. 모든 단어를 색인하는 저장소는 색인 크기와 디스크를 봐요. 라벨만 색인하는 저장소는 스트림 수가 갑자기 늘지 않는지 봐요.

"로그 검색이 느리다"는 말도 저장 방식에 따라 뜻이 달라요. 라벨만 색인하는 저장소에서 넓은 범위의 본문 검색이 느린 건 설계대로예요. 줄이는 법은 <Term slug="logs/slow-search">로그 검색이 느릴 때</Term>에 있어요.

</Checkpoints>

<Deeper>
  ### 스트림이란

  Loki에서 스트림은 같은 라벨 묶음을 가진 로그의 흐름이에요. 라벨 값 하나만 달라도 다른 스트림이에요. 그래서 라벨 값의 조합 수가 곧 스트림 수예요.

  ### 라벨로 좋은 값

  Loki 문서는 지역, 클러스터, 서버, 앱, 네임스페이스, 환경처럼 값의 종류가 정해진 것을 라벨로 권해요. 값이 끝없이 늘 수 있는 것은 라벨로 쓰지 말라고 해요.
</Deeper>
