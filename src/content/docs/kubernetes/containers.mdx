  표준 화물 컨테이너와 같아요. 안에 무엇이 들었든 같은 크기라 같은 크레인과 배로 옮겨요. 배의 엔진(커널)은 여러 컨테이너가 함께 써요.
</Analogy>

## 이미지

<Term term="kubernetes/container-image">컨테이너 이미지</Term>는 앱과 그 앱이 쓰는 모든 것을 묶은 파일이에요. 이 이미지를 실행한 것이 <Term term="kubernetes/container">컨테이너</Term>예요. 같은 이미지는 노트북에서도, 운영 서버에서도 같은 내용으로 돌아요.

이미지는 `nginx:1.27`처럼 이름과 태그로 가리켜요. 태그를 빼면 쿠버네티스는 `latest` 태그로 알아들어요. 태그는 나중에 다른 이미지를 가리키도록 바뀔 수 있어서, 정확히 같은 이미지를 원하면 다이제스트(이미지 내용의 지문)로 가리켜요.

## 격리: 네임스페이스

컨테이너 안의 프로세스는 서버의 다른 프로세스를 보지 못해요. 리눅스 커널의 <Term term="kubernetes/linux-namespace">네임스페이스</Term> 기능 덕분이에요. 네임스페이스는 서버 전체의 자원을, 그 안의 프로세스에게는 자기만의 것처럼 보이게 감싸요.

| 네임스페이스 | 따로 보이게 하는 것 |
| --- | --- |
| PID | 프로세스 번호 |
| Network | 네트워크 장치, 포트 |
| Mount | 파일 시스템의 마운트 |
| UTS | 호스트 이름 |
| User | 사용자와 그룹 번호 |

쿠버네티스에도 "네임스페이스"라는 같은 이름의 기능이 있어요. 이건 클러스터 안의 객체를 팀이나 용도별로 나누는 이름 묶음이라, 리눅스 네임스페이스와는 다른 거예요.

## 자원 제한: cgroup

<Term term="kubernetes/cgroup">cgroup</Term>은 프로세스를 묶어, 그 묶음이 쓰는 자원을 제한하고 재는 리눅스 커널 기능이에요. 컨테이너가 쓸 수 있는 CPU와 메모리의 한도는 이 기능으로 걸어요.

그래서 컨테이너의 CPU·메모리 숫자는 서버 전체 숫자가 아니라, 그 컨테이너의 cgroup이 센 값으로 봐야 해요.

## 모니터링에서는

컨테이너 화면은 컨테이너마다 CPU와 메모리 사용량을 보여 줘요. 이 값은 컨테이너의 cgroup에서 와요. 서버 전체 사용률과 따로 보고, 걸어 둔 한도와 견줘 봐요.

<Checkpoints>
  <Check>운영 배포의 이미지가 `latest` 태그라면 다시 보세요. 같은 태그가 다른 이미지를 가리킬 수 있어서, 언제 무엇이 배포됐는지 알기 어려워요.</Check>
  <Check>컨테이너 메모리 한도와 자바의 `-Xmx`를 같게 잡았다면 다시 보세요. JVM은 힙 밖에서도 메모리를 써서 한도를 넘길 수 있어요. 자세한 건 <Term slug="apm/jvm-memory">JVM과 힙 메모리</Term>에 있어요.</Check>
  <Check>컨테이너를 가상 머신처럼 강한 보안 경계로 여기는 설계라면 다시 보세요. 컨테이너는 서버의 커널을 함께 써요.</Check>
</Checkpoints>

<Deeper>
  ### 네임스페이스의 종류

  리눅스에는 위 표 말고도 네임스페이스가 세 가지 더 있어요. IPC는 프로세스 간 통신 자원을, Cgroup은 cgroup 루트 디렉터리를, Time은 부팅·단조 시계를 따로 보이게 해요.

  ### 다이제스트로 가리키기

  다이제스트는 이미지의 특정 버전 하나만 가리켜요. 그래서 이름과 다이제스트로 지정하면, 컨테이너를 띄울 때마다 같은 코드가 돌아요.
</Deeper>
