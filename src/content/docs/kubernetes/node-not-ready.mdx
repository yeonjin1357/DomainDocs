## 1. Ready 조건의 값을 보세요

노드는 몇 가지 조건(condition)으로 상태를 알려요. 가장 중요한 건 Ready예요.

| Ready 값 | 뜻 |
| --- | --- |
| True | 노드가 건강하고 파드를 받을 수 있어요 |
| False | 노드가 아프고 파드를 받지 않아요 |
| Unknown | 노드 컨트롤러가 정해진 시간(기본 50초) 동안 노드 소식을 못 들었어요 |

Unknown이라면 노드 쪽 kubelet이 컨트롤 플레인과 연락이 끊긴 거예요. 노드가 꺼졌거나, 네트워크가 끊겼거나, kubelet이 멈췄어요. 이때는 노드를 서버로 보고 <Term slug="server/server-not-reporting">서버 수집이 끊겼을 때</Term>의 순서로 봐요.

**확인 방법**: `kubectl describe node 노드이름`의 Conditions 칸을 봐요. Ready의 값과 바뀐 시각, 메시지가 있어요.

## 2. 압박 조건이 켜졌는지 보세요

Ready 말고도 노드는 자원 압박을 따로 조건으로 알려요. 압박만으로는 NotReady가 되지 않아서, Ready가 True인 채 이 조건만 켜져 있기도 해요. 대신 새 파드가 오지 않도록 노드에 taint가 붙어요.

| 조건 | True일 때 |
| --- | --- |
| MemoryPressure | 노드 메모리가 모자라요 |
| DiskPressure | 노드 디스크 용량이 모자라요 |
| PIDPressure | 노드에 프로세스가 너무 많아요 |

압박 조건이 켜지면 kubelet은 노드를 지키려고 파드를 쫓아내기 시작해요. 이걸 노드 압박 축출(node-pressure eviction)이라고 해요. 기본 기준은 리눅스 노드에서 쓸 수 있는 메모리 100Mi 미만, 노드 파일 시스템 여유 10% 미만 같은 값이에요.

디스크 압박이라면 노드의 로그와 컨테이너 이미지가 쌓이지 않았는지 봐요. 서버 디스크를 보는 순서는 <Term slug="server/disk-filling-up">디스크가 차오를 때</Term>와 같아요.

## 3. 그 위 파드에 무슨 일이 생기는지 알아 두세요

노드가 NotReady나 연락 끊김이 되면, 쿠버네티스는 그 노드에 taint를 붙여요. 그리고 파드마다 이 taint를 5분(300초) 동안 견디는 toleration을 자동으로 붙여 둬요.

그래서 노드가 짧게 끊겼다 돌아오면 파드는 그대로 남아요. 5분 넘게 돌아오지 않으면 Deployment 같은 워크로드가 다른 노드에 새 파드를 띄워요. 그사이 몇 분은 원하는 개수보다 적은 파드로 버텨야 해요.

## 4. 노드 안에서 kubelet을 보세요

노드에 들어갈 수 있다면 kubelet이 도는지, 무슨 로그를 남겼는지 봐요. 컨테이너 런타임이 멈췄거나, 인증서가 만료됐거나, 노드 자원이 바닥나 kubelet이 버티지 못하는 경우가 있어요.

**확인 방법**: kubelet이 systemd 서비스라면 `systemctl status kubelet`으로 상태를 봐요. 로그는 `journalctl -u kubelet`으로 봐요.
