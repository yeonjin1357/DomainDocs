## 1. 축출 메시지를 읽으세요

쫓겨난 파드는 지워지지 않고 상태가 Failed, 이유가 Evicted인 채로 남아요. 메시지에 무엇이 모자랐는지 나와요.

```text
Status:   Failed
Reason:   Evicted
Message:  The node was low on
          resource: memory.
```

메시지는 크게 네 가지예요.

| 메시지 | 뜻 |
| --- | --- |
| The node was low on resource: memory | 노드 메모리가 모자라요 |
| The node was low on resource: ephemeral-storage | 노드 디스크가 모자라요 |
| Pod ephemeral local storage usage exceeds the total limit of containers | 파드가 자기 임시 저장 한도를 넘었어요 |
| Usage of EmptyDir volume … exceeds the limit | emptyDir 볼륨이 정한 크기를 넘었어요 |

앞의 둘은 노드 전체가 모자란 경우예요. 뒤의 둘은 노드는 괜찮은데 파드가 자기 한도를 넘은 경우예요.

**확인 방법**: `kubectl describe pod 파드이름`의 Status, Reason, Message를 봐요. 같은 내용이 파드의 Evicted 이벤트에도 남아요.

OOMKilled는 컨테이너만 다시 시작해서, 파드의 재시작 횟수가 올라가요. 이건 <Term slug="kubernetes/pod-restarting">파드가 계속 재시작될 때</Term>에서 다뤄요.

Evicted 파드는 다시 시작하지 않아요. Deployment 같은 워크로드가 대신할 새 파드를 만들고, 스케줄러가 놓을 노드를 다시 골라요.

## 3. 노드 압박이라면 기준과 순서를 보세요

kubelet은 노드의 남은 자원이 기준 아래로 내려가면 압박 조건을 켜고 파드를 내보내요. 리눅스 노드의 기본 기준은 이래요.

| 신호 | 기본 기준 | 켜지는 조건 |
| --- | --- | --- |
| `memory.available` | 100Mi 미만 | MemoryPressure |
| `nodefs.available` | 10% 미만 | DiskPressure |
| `imagefs.available` | 15% 미만 | DiskPressure |
| `nodefs.inodesFree` | 5% 미만 | DiskPressure |
| `imagefs.inodesFree` | 5% 미만 | DiskPressure |

nodefs는 kubelet과 파드 로그, emptyDir가 쓰는 노드의 주 파일 시스템이에요. imagefs는 컨테이너 런타임이 이미지를 따로 두는 파일 시스템이에요. 따로 없으면 둘은 같은 디스크예요.

메모리가 모자랄 때 쫓겨나는 순서는 이래요.

1. 요청보다 더 쓰고 있는 파드부터예요. 그 안에서는 우선순위가 낮은 파드, 요청보다 더 많이 넘긴 파드가 먼저예요.
2. 요청 안에서 쓰고 있는 파드는 마지막이에요. 그 안에서도 우선순위가 낮은 파드가 먼저예요.

요청을 하나도 안 적은 BestEffort 파드는 조금만 써도 요청을 넘은 셈이라 앞쪽에 서요. 메모리 요청을 실제보다 낮게 적은 파드도 마찬가지예요. 원리는 <Term slug="kubernetes/requests-and-limits">요청과 한도</Term>에 있어요.

## 4. 디스크 압박이라면 무엇이 찼는지 보세요

디스크가 모자라면 kubelet은 파드를 내보내기 전에 먼저 치워요. 끝난 컨테이너를 지우고, 쓰지 않는 이미지를 지워요. 그래도 모자라면 디스크를 많이 쓰는 파드부터 내보내요.

파드가 노드 디스크를 쓰는 곳은 세 군데예요.

- 컨테이너 안에 쓴 파일이에요. 컨테이너의 쓰기 레이어에 쌓여요.
- emptyDir 볼륨이에요.
- 컨테이너 로그예요.

앱이 로그나 임시 파일을 컨테이너 안에 계속 쌓으면, 그 파일이 모두 노드 디스크를 차지해요. 노드 디스크를 보는 순서는 <Term slug="server/disk-filling-up">디스크가 차오를 때</Term>와 같아요.

이런 쓰기는 <Term term="kubernetes/ephemeral-storage">임시 저장 공간</Term>(ephemeral-storage)으로 요청·한도를 정할 수 있어요. 한도를 넘은 파드는 노드 압박을 기다리지 않고 바로 내보내져요. 1단계의 뒤쪽 두 메시지가 이 경우예요.

## 5. 쫓겨난 파드를 정리하세요

Evicted 파드는 누가 지울 때까지 목록에 남아요. 컨트롤 플레인은 끝난 파드가 기본 12,500개를 넘어야 지우기 시작해요.

그래서 Evicted 파드 7개가 보여도, 대신할 새 파드는 이미 떠 있을 수 있어요. 워크로드의 준비된 파드 수부터 봐요. 원인을 확인했다면 `kubectl delete pod --field-selector=status.phase=Failed`로 끝난 파드를 지워요.

노드를 비우는 `kubectl drain`도 축출이라고 불러요. 하지만 이때는 API 서버가 파드를 지워서, Evicted 파드로 남지 않아요.

## 하드 기준은 기다려 주지 않아요

위 표의 기본 기준은 하드 기준이에요. 하드 기준에 닿으면 kubelet은 파드에 끝낼 시간을 주지 않고 바로 멈춰요. 그래서 처리 중이던 요청이 끊기고, 그 순간 에러가 튈 수 있어요.

관리자가 소프트 기준을 따로 두면, 그 상태가 정한 시간 동안 이어질 때만 내보내요. 이때는 끝낼 시간을 줄 수 있어요.
