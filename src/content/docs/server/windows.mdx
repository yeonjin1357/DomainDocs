  </Point>

  </Point>

## 성능 카운터 읽기

윈도우는 시스템 상태를 <Term term="server/performance-counter">성능 카운터</Term>로 내놓아요. 경로는 `\객체(인스턴스)\카운터` 꼴이고, `_Total`은 인스턴스를 모두 합친 값이에요. PowerShell의 `Get-Counter`로 읽어요.

먼저 볼 카운터는 이래요.

- `\Processor(_Total)\% Processor Time`: 모든 논리 CPU를 합친 사용률이에요.
- `\System\Processor Queue Length`: CPU를 기다리는 스레드 수예요.
- `\Memory\Available MBytes`: 프로세스에 바로 내줄 수 있는 메모리(MB)예요.
- `\Memory\Committed Bytes`, `\Memory\Commit Limit`: 약속해 둔 가상 메모리와 그 한도예요.
- `\LogicalDisk(C:)\% Free Space`: C 드라이브의 남은 공간 비율이에요.
- `\PhysicalDisk(_Total)\Avg. Disk sec/Read`: 읽기 한 번에 걸린 평균 시간이에요.

## 리눅스와 뜻이 다른 숫자

이름이 비슷해도 세는 법이 다른 숫자가 있어요. 리눅스 기준으로 읽으면 판단이 틀려요.

Processor Queue Length는 모든 CPU가 함께 쓰는 줄 하나의 길이예요. 그래서 논리 CPU 수로 나눠 봐요. 윈도우 설명은 CPU 하나에 10개 이하라면 대개 괜찮다고 해요.

`Avg. Disk sec/Read`는 초 단위예요. 0.020이면 20밀리초예요. 단위를 밀리초로 알고 읽으면 디스크가 1,000배 빨라 보여요.

`Available MBytes`는 비어 있는 메모리에 캐시처럼 곧 비울 수 있는 몫까지 더한 값이에요. 리눅스의 available과 비슷하게 읽어요. Committed Bytes가 Commit Limit에 가까워지면 약속할 수 있는 메모리가 바닥나는 중이에요.

## 서비스는 SCM이 관리해요

윈도우의 서비스는 서비스 제어 관리자(SCM)가 띄우고 멈춰요. 서비스마다 상태(Running, Stopped)와 시작 방식(Automatic, Manual, Disabled)이 있어요. `Get-Service`로 둘 다 볼 수 있어요.

서비스가 죽었을 때 다시 띄울지는 서비스의 복구 설정으로 정해요. 리눅스 systemd의 `Restart=`와 같은 일이에요.

그래서 상태가 Running이어도 몇 번 죽었다 살아났을 수 있어요. systemd 쪽은 <Term slug="server/services-and-logs">서비스와 시스템 로그</Term>에서 다뤄요.

## 기록은 이벤트 로그에 모여요

윈도우의 기록은 <Term term="server/event-log">이벤트 로그</Term>에 모여요. 운영체제 기록은 System, 앱 기록은 Application, 보안 기록은 Security 로그예요. 기록마다 수준(Critical, Error, Warning, Information)과 이벤트 ID가 붙어요.

<Figure caption="서버가 다시 켜진 이유와 서비스가 죽은 기록을 가를 때 먼저 보는 System 로그의 이벤트예요.">
  <Strip

      },

- **6008**(EventLog): 직전 종료가 예기치 않았다는 기록이에요. 전원이 끊기거나 시스템이 멈췄을 때 남아요.
- **1074**(User32): 사람이나 프로세스가 재시작이나 종료를 시작했다는 기록이에요. 누가 시작했는지도 적혀요.
- **7034**(Service Control Manager): 서비스가 예기치 않게 끝났고, 몇 번째인지 적혀요.
- **7031**(Service Control Manager): 서비스가 끝나서 정해 둔 복구 동작을 한다는 기록이에요.

PowerShell에서는 `Get-WinEvent`로 이벤트 ID를 골라 읽어요.

```powershell
Get-WinEvent -FilterHashtable @{
  LogName = 'System'
  Id = 6008, 1074
} -MaxEvents 5
```

Prometheus로 모은다면 windows_exporter를 써요. 기본으로 9182번 포트에서 지표를 보여 주고, cpu, memory, logical_disk, service 수집기가 기본으로 켜져 있어요. 리눅스의 node_exporter와 지표 이름이 달라요.

CPU 시간은 `windows_cpu_time_seconds_total`이에요. `mode` 레이블에 user, privileged, idle 같은 쓰임새가 들어가요. privileged는 커널 코드를 실행한 시간이라 리눅스의 sy에 가까워요.

서비스 상태는 `windows_service_state`가 지금 상태에만 1을 내요.

리눅스 서버와 같은 화면에 놓을 때는 지표마다 짝을 맞춰야 해요. 서버 지표가 화면까지 오는 길은 <Term slug="server/metrics-sources">서버 지표는 어디서 오나</Term>에서 다뤄요.

<Deeper>
  ### 한국어 윈도우의 카운터 이름

  한국어 윈도우에서는 화면에 카운터 이름이 한국어로 보이기도 해요. 그래도 `Get-Counter`에 영어 경로를 넘기면 읽혀요. 이 글의 경로는 한국어 윈도우에서 읽어 확인했어요.

  ### 이벤트 로그도 덮어써요

  이벤트 로그는 정한 크기가 차면 오래된 기록부터 덮어써요. System 로그의 기본 방식이 이래서, 오래전 재시작 기록은 남아 있지 않을 수 있어요.

  ### 한 번에 여러 번 읽기

  `Get-Counter`에 `-SampleInterval`과 `-MaxSamples`를 주면 정한 간격으로 여러 번 읽어요. `\Processor(_Total)\% Processor Time`을 2초 간격으로 세 번 읽는 식이에요.
</Deeper>
