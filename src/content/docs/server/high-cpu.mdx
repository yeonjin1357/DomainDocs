## 1. CPU 시간을 종류별로 나눠 보세요

사용률 하나보다 그 안의 몫이 다음 단계를 정해요. 종류별 뜻은 <Term slug="server/cpu-usage">CPU 사용률과 부하</Term>에 있어요.

- **us(사용자)가 늘었다면**: 앱 코드가 일을 많이 해요. 2단계로 가서 프로세스를 찾아요.
- **sy(시스템)가 늘었다면**: 앱이 커널을 아주 자주 불러요. 예를 들어 아주 작은 단위로 자주 읽고 쓰거나, 연결을 자주 맺고 끊는 동작을 의심해요.
- **st(steal)가 늘었다면**: 가상 머신에서 다른 가상 머신에 CPU를 빼앗기고 있어요. 서버 안이 아니라 호스트나 클라우드 쪽을 봐요.
- **wa(iowait)만 늘었다면**: CPU가 바쁜 게 아니라 디스크를 기다려요. <Term slug="server/disk-io">디스크 입출력</Term>을 봐요.

**확인 방법**: `mpstat -P ALL 5`로 코어별 몫을 5초마다 봐요. %steal은 하이퍼바이저가 다른 가상 CPU를 돌보는 동안 기다린 비율이에요.

## 2. 어느 프로세스가 썼는지 찾으세요

프로세스별 CPU 사용률에서 순위가 바뀌었거나 새로 올라온 프로세스를 찾아요. 프로세스 사용률은 코어 하나를 100%로 세서, 여러 코어를 쓰면 100%를 넘어요.

범인 프로세스를 찾았다면, 그 안의 어느 스레드가 바쁜지까지 내려가요. 자바라면 <Term slug="apm/thread-dumps">스레드 덤프</Term>를 몇 번 떠서 바쁜 스레드가 무슨 코드를 실행하는지 봐요.

**확인 방법**: `pidstat -u 5`로 프로세스별 %usr, %system을 봐요. `top`에서 `H`를 누르면 스레드 단위로 보여 줘요.

## 3. 일이 밀리고 있는지 보세요

CPU가 95%여도 일이 밀리지 않으면 아직 감당하고 있는 거예요. 부하가 코어 수보다 커지면 차례를 기다리는 일이 생겨 응답이 느려져요.

## 4. 언제부터, 무엇과 함께 늘었는지 맞춰 보세요

CPU가 오른 시각을 다른 사건과 나란히 놓아요. 배포, 배치 작업, 요청 증가, 가비지 컬렉션이 흔한 원인이에요.

- 요청 수가 함께 늘었다면 부하가 는 거예요. 서버를 늘리거나 요청을 나눠요.
- 요청 수는 그대로인데 CPU만 늘었다면, 요청 하나가 더 무거워졌어요. 배포된 코드나 데이터 변화를 봐요.
- 일정한 시각마다 오른다면 정해진 작업(백업, 배치, cron)을 먼저 봐요.
