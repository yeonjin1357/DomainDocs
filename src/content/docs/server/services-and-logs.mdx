<Term term="server/service">서비스</Term>는 화면 없이 뒤에서 계속 도는 프로그램이에요. 웹 서버, DB, 모니터링 에이전트가 모두 서비스예요. 데몬(daemon)이라고도 불러요.

많은 리눅스 배포판은 부팅 때 <Term term="server/systemd">systemd</Term>를 가장 먼저 띄워요. 그래서 systemd의 PID는 1이에요. systemd가 나머지 서비스를 차례로 띄워요.

서비스마다 유닛 파일이 하나씩 있어요. 무엇을 실행할지, 부팅 때 띄울지, 죽으면 다시 띄울지를 적은 설정 파일이에요. 이름은 `nginx.service`처럼 `.service`로 끝나요.

## 서비스 상태는 Active 줄로 읽어요

`systemctl status 서비스이름`은 서비스 상태를 한눈에 보여 줘요. 가장 먼저 볼 줄은 Active예요.

| Active 값 | 뜻 |
| --- | --- |
| active (running) | 돌고 있어요 |
| inactive | 멈춰 있어요. 멈추라고 했거나 아직 띄우지 않았어요 |
| activating | 띄우는 중이에요 |
| failed | 죽었거나, 에러 코드로 끝났거나, 정한 시간 안에 뜨지 못했어요 |

Active 줄에는 언제부터 그 상태인지(since)도 나와요. 서비스를 다시 띄우면 이 시각도 새로 바뀌어요.

Loaded 줄에는 유닛 파일의 위치와 enabled 여부가 나와요. enabled는 부팅 때 저절로 띄운다는 뜻이에요. status 아래에는 그 서비스의 최근 로그 몇 줄도 붙어 나와요.

## 죽으면 다시 띄울지 정해요

서비스가 죽었을 때 다시 띄울지는 유닛 파일의 `Restart=`로 정해요. 기본값 `no`는 다시 띄우지 않아요. 문서는 오래 도는 서비스에 `on-failure`를 권해요.

`on-failure`는 에러 코드로 끝나거나, 신호를 받아 죽거나, 정한 시간을 넘기면 다시 띄워요. 기본으로 100ms 쉬었다가 띄워요.

## 로그는 journald에 모여요

<Term term="server/journald">journald</Term>(systemd-journald)는 여러 곳의 로그를 받아 한곳에 저장해요. 서비스가 표준 출력과 표준 에러로 내보낸 글, syslog로 보낸 메시지, 커널 메시지가 모두 여기로 와요.

읽을 때는 `journalctl`을 써요.

| 명령 | 보여 주는 것 |
| --- | --- |
| `journalctl -u nginx` | nginx 로그 |
| `journalctl -k` | 커널 메시지 |
| `journalctl -b -1` | 지난 부팅 로그 |
| `journalctl --list-boots` | 부팅 목록 |

`-k`는 이번 부팅의 커널 메시지만 보여 줘요. `--list-boots`는 부팅마다 첫 기록과 마지막 기록의 시각을 함께 보여 줘요.

앱이 따로 파일에 쓰는 로그는 journald를 거치지 않아요. 그런 로그는 그 파일을 직접 읽어야 해요.

## 저널은 재부팅 때 사라질 수 있어요

저널을 어디에 둘지는 `journald.conf`의 `Storage=`로 정해요. 디스크(`/var/log/journal`)에 두면 재부팅 뒤에도 남아요. 메모리(`/run/log/journal`)에만 두면 재부팅 때 사라져요.

기본값은 systemd를 빌드할 때 정해져서, 배포판과 버전마다 다를 수 있어요. 재부팅 전 로그가 필요한 서버라면 디스크에 남는지 미리 확인해요.

<Deeper>
  ### 유닛 파일은 어디에 있나

  관리자가 만든 유닛 파일은 `/etc/systemd/system`에 둬요. 패키지가 설치한 유닛 파일은 `/usr/lib/systemd/system`에 있어요. `systemctl status`의 Loaded 줄에 실제로 읽은 파일의 경로가 나와요.

  ### 재시작 한도

  한도는 유닛 파일의 `StartLimitIntervalSec=`와 `StartLimitBurst=`로 정해요. 따로 정하지 않으면 시스템 설정의 기본값(10초, 5번)을 따라요. 이 한도는 다시 띄우기뿐 아니라 손으로 띄우는 것까지 모두 세요.

  한도에 걸린 서비스는 `systemctl reset-failed`로 횟수를 비운 뒤 다시 띄울 수 있어요. 죽는 원인을 고치지 않으면 같은 일이 되풀이돼요.

  ### 저널의 크기

  디스크에 둔 저널은 기본으로 그 파일 시스템의 10%까지 써요. 다른 쓰임을 위해 15%는 비워 두고, 두 값 모두 4G를 넘지 않아요. `journald.conf`의 `SystemMaxUse=`와 `SystemKeepFree=`로 바꿔요.

  ### dmesg -T의 시각

  `dmesg -T`는 커널 메시지에 사람이 읽는 시각을 붙여 보여 줘요. 문서는 이 시각이 부정확할 수 있다고 경고해요. 절전(suspend) 뒤에는 시각 계산이 어긋나요.
</Deeper>
