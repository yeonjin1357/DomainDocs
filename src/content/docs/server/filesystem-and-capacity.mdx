<KeyPoints>
  <Point title="파일 내용과 파일 정보는 따로 둬요">
    파일 시스템은 내용을 담는 데이터 블록과, 파일 정보를 담는 inode를 따로 관리해요.
  </Point>
  <Point title="공간이 남아도 inode가 차면 못 써요">
    작은 파일이 아주 많으면 inode가 먼저 바닥나요. 그러면 용량이 남아도 새 파일을 만들 수 없어요.
  </Point>
  <Point title="지운 파일이 공간을 계속 쥘 수 있어요">
    프로세스가 열어 둔 파일은 지워도 그 프로세스가 닫을 때까지 공간이 남아 있어요.
  </Point>
</KeyPoints>

<Analogy limit="캐비닛은 색인 카드를 더 사 오면 되지만, ext4 같은 파일 시스템은 만들 때 정한 inode 비율을 나중에 바꿀 수 없어요.">
  파일 시스템은 캐비닛과 색인 카드 상자를 함께 쓰는 정리법이에요. 서류는 서랍(데이터 블록)에, 서류마다 위치와 정보를 적은 카드(inode)는 상자에 넣어요. 서랍에 자리가 남아도 카드가 다 떨어지면 새 서류를 넣을 수 없어요.
</Analogy>

<Term term="server/file-system">파일 시스템</Term>은 디스크에 파일을 정리해 두는 방식이에요. 파일마다 <Term term="server/inode">inode</Term>가 하나씩 있고, 여기에 크기, 권한, 시각, 내용이 든 블록의 위치 같은 정보가 담겨요.

ext4 같은 파일 시스템은 만들 때 inode 수를 정해 둬요. 그래서 용량과 inode, 두 가지가 따로 찰 수 있어요.

`df`는 파일 시스템마다 남은 공간을, `df -i`는 남은 inode를 보여 줘요. inode가 다 차면 새 파일을 만들려 할 때 "공간이 없다"는 오류(ENOSPC)가 나요. 용량은 넉넉한데 이 오류가 나면 inode부터 봐요.

## 지웠는데 공간이 안 늘어요

로그 파일을 지웠는데 `df`의 남은 공간이 그대로일 때가 있어요. 그 파일을 열어 둔 프로세스가 아직 있기 때문이에요.

리눅스는 파일 이름을 지워도, 그 파일을 연 프로세스가 모두 닫을 때까지 내용을 지우지 않아요. 앱이 계속 쓰고 있는 로그를 지우면, 이름만 사라지고 공간은 앱을 다시 시작할 때까지 그대로예요.

## 다 차지 않았는데 꽉 찼대요

ext4 같은 파일 시스템은 기본으로 전체 블록의 5%를 관리자(root) 몫으로 남겨 둬요. 디스크가 꽉 차도 root로 도는 시스템 프로그램이 계속 일할 수 있게 하려는 거예요.

그래서 일반 사용자로 도는 앱은 실제로 95%쯤에서 공간이 없다는 오류를 만나요. 사용률을 계산할 때 이 몫을 빼지 않으면, 화면은 여유가 있다고 보여 주는데 앱은 쓰지 못해요.

<Deeper>
  ### inode 비율은 만들 때 정해요

  ext2·ext3·ext4는 파일 시스템을 만들 때 몇 바이트마다 inode 하나를 둘지(bytes-per-inode) 정해요. 매뉴얼은 만든 뒤에는 이 비율을 바꿀 수 없다고 경고해요. 작은 파일이 아주 많을 서버라면 만들 때 inode를 넉넉히 잡아요.

  ### 예약 공간의 쓰임

  예약 공간은 조각남을 줄이고, syslogd 같은 root 프로그램이 디스크가 꽉 찬 뒤에도 일할 수 있게 해요. 비율은 파일 시스템을 만들 때 바꿀 수 있어요.

  ### 지운 파일이 남는 이유

  파일 이름은 inode를 가리키는 연결(link)이에요. 마지막 연결을 지워도, 그 파일을 연 프로세스가 있으면 마지막 파일 디스크립터가 닫힐 때까지 파일이 남아 있어요.
</Deeper>
