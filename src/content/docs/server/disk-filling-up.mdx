## 1. 어느 파일 시스템의 무엇이 찼는지 보세요

디스크가 찼다는 말은 두 가지 뜻이에요. 데이터를 담을 공간이 다 찼거나, 파일 수를 세는 <Term term="server/inode">inode</Term>가 다 찼거나예요. 둘 중 하나만 차도 새 파일을 만들 수 없어요.

자세한 건 <Term slug="server/filesystem-and-capacity">파일 시스템과 디스크 용량</Term>에 있어요.

**확인 방법**: `df -h`로 파일 시스템별 용량을, `df -i`로 inode 사용률을 봐요. 작은 파일이 아주 많은 디렉터리가 있으면 용량은 남았는데 inode만 찰 수 있어요.

## 2. 무엇이 늘었는지 찾으세요

찬 파일 시스템 안에서 어느 디렉터리가 큰지 위에서부터 좁혀 가요. 다른 파일 시스템이 걸려 있는 디렉터리는 건너뛰어야 숫자가 섞이지 않아요.

**확인 방법**: `du -xh --max-depth=1 /var | sort -h`로 바로 아래 디렉터리 크기를 봐요. `-x`는 다른 파일 시스템으로 넘어가지 않게 해요. 가장 큰 곳으로 들어가 같은 일을 되풀이해요.

흔한 범인은 이런 것들이에요.

- 회전(rotation)되지 않는 로그 파일이 계속 커져요. 회전 방식은 <Term slug="foundations/log-collection">로그가 모이는 길</Term>에서 다뤄요.
- 지우지 않은 백업, 덤프, 임시 파일이 쌓여요.
- 데이터베이스의 표나 로그가 커져요. <Term slug="database/storage-growing">DB 저장 공간이 계속 늘 때</Term>를 봐요.
- 데이터의 보관 기간이 길게 잡혀 있어요. Kafka라면 <Term slug="messaging/retention">보관과 정리</Term>를 봐요.

## 3. 지웠는데 안 줄어든다면 열린 파일을 찾으세요

큰 로그 파일을 지웠는데 `df`의 사용량이 그대로일 때가 있어요. 그 파일을 아직 열고 있는 프로세스가 있으면, 이름만 사라지고 공간은 프로세스가 닫을 때까지 남아요.

`df`와 `du`의 숫자가 크게 다르다면 거의 이 경우예요. `df`는 파일 시스템이 쓴 공간을, `du`는 이름이 남아 있는 파일만 세기 때문이에요.

**확인 방법**: `lsof +L1`로 지워졌지만 열려 있는 파일과, 그 파일을 연 프로세스를 찾아요. 그 프로세스를 다시 시작하거나 로그 파일을 다시 열게 하면 공간이 돌아와요.

## 4. 얼마나 남았는지 시간으로 바꿔 보세요

사용률 숫자보다 "언제 다 차는가"가 더 쓸모 있어요. 지난 며칠 동안 늘어난 속도로, 남은 공간을 다 쓰는 데 걸리는 시간을 계산해요.

예를 들어 남은 공간이 50GB이고 하루에 10GB씩 는다면 5일이 남아요. 같은 95%라도 하루에 0.1GB씩 느는 서버와는 급한 정도가 달라요. 알림에 이 남은 시간을 함께 보여 주면, 무엇부터 손볼지 정하기 쉬워요.
