  <Point title="사용률은 일한 시간의 비율이에요">
    커널은 CPU가 어떤 일에 시간을 썼는지 계속 쌓아 세요. 일정 구간의 차이로 그동안 일한 비율을 구해요.
  </Point>
  <Point title="부하는 줄 선 일의 수예요">
    실행 중이거나 차례를 기다리는 일, 리눅스에서는 디스크를 기다리는 일까지 세요. 코어 수와 견줘 읽어요.
  </Point>
  <Point title="100%가 넘어도 정상일 수 있어요">
    프로세스 사용률은 보통 코어 하나를 100%로 세요. 코어 4개를 다 쓰는 프로세스는 400%로 보여요.
  </Point>
</KeyPoints>

<Analogy limit="사무실에서는 서류를 기다리는 사람을 대기 줄에 세지 않아요. 리눅스 부하는 디스크를 기다리느라 CPU를 쓰지 않는 일까지 세서, CPU가 한가해도 부하가 높을 수 있어요.">
  직원 4명(코어 4개)이 일하는 사무실이에요. 사용률은 직원들이 책상에서 실제로 일한 시간의 비율이에요. 부하는 지금 일하는 사람과 책상이 비기를 기다리며 줄 선 사람을 합친 수예요.
</Analogy>

## CPU 시간은 이렇게 나눠 세요

커널은 CPU 시간을 하는 일에 따라 나눠 세요. `top` 같은 도구의 CPU 줄에 나오는 이름이에요.

| 이름 | 뜻 |
| --- | --- |
| us | 앱(사용자 영역) 코드를 실행한 시간 |
| sy | 커널 코드를 실행한 시간 |
| ni | 우선순위를 낮춘(nice) 프로세스를 실행한 시간 |
| id | 할 일이 없어 쉰 시간 |
| wa | 쉬는 동안 입출력 완료를 기다린 일이 있던 시간(iowait) |
| hi·si | 하드웨어·소프트웨어 인터럽트를 처리한 시간 |
| st | 가상 머신에서 다른 가상 머신에 빼앗긴 시간(steal) |

sy가 높으면 앱이 시스템 콜을 아주 많이 부르거나 커널이 바쁜 거예요. st는 가상 머신에서만 의미가 있어요. 같은 물리 서버의 다른 가상 머신이 CPU를 가져간 시간이에요.

## 사용률은 누적값의 차이로 구해요

`/proc/stat`의 CPU 시간은 부팅 뒤 계속 늘어나는 누적값이에요. 그래서 사용률은 두 시점의 값을 빼서 구해요. 누적값을 다루는 법은 <Term slug="foundations/counters-and-rate">카운터와 rate</Term>와 같아요.

예를 들어 코어 4개짜리 서버를 10초 간격으로 읽었다고 해 봐요. 이 단위(USER_HZ)가 1초에 100이면, 10초 동안 CPU 시간은 모두 4 × 10 × 100 = 4,000이에요. 그중 id가 1,000 늘었다면 사용률은 (4,000 − 1,000) ÷ 4,000 = 75%예요.

## 부하는 줄 선 일의 수예요

리눅스의 <Term term="server/load-average">부하</Term>(load average)는 실행 중이거나 실행 대기 줄에 선 일(R 상태)과, 디스크 입출력을 기다리는 일(D 상태)의 수예요. 1분, 5분, 15분 동안의 평균으로 보여 줘요.

부하는 코어 수와 견줘 읽어요. 코어 4개 서버의 부하 4는 딱 맞게 바쁜 거고, 부하 8이면 평균 4개가 차례를 기다려요. 같은 부하 8도 코어 16개 서버에서는 여유가 있어요.

서버 화면의 CPU 그래프는 보통 서버 전체 코어의 평균 사용률이에요. 프로세스 목록의 CPU 사용률은 프로세스마다 코어 하나를 100%로 세는 경우가 많아요. 두 숫자의 기준이 달라요.

사용률은 CPU가 얼마나 바쁜지, 부하는 일이 얼마나 밀렸는지를 보여 줘요. 둘을 함께 보면 CPU가 모자란 건지, 다른 곳을 기다리는 건지 나눌 수 있어요.

  <Check>가상 머신에서 st(steal)가 높다면 앱이 아니라 같은 물리 서버의 다른 가상 머신을 의심하세요.</Check>

<Deeper>
  ### iowait를 믿기 어려운 이유

  리눅스 매뉴얼은 iowait가 믿을 만하지 않다고 하며 이유를 들어요. CPU는 입출력을 기다리지 않아요. 입출력을 기다리는 건 작업이고, 그동안 CPU는 쉬거나 다른 작업을 실행해요.

  여러 코어가 있으면 입출력을 기다리는 작업은 어느 코어에서도 실행 중이 아니라, 코어별 iowait를 계산하기 어려워요. 어떤 조건에서는 이 값이 줄어들기도 해요.

  ### 코어별 줄

  `/proc/stat`에는 전체 합계 줄(`cpu`) 말고도 코어마다 줄(`cpu0`, `cpu1`, …)이 있어요. 코어별 사용률은 이 줄로 계산해요.

  ### 부하의 넷째 칸

  `/proc/loadavg`의 넷째 칸은 지금 실행할 수 있는 스케줄링 단위(프로세스·스레드)의 수와, 전체 수를 빗금으로 이어 보여 줘요. 예를 들어 `3/412`예요.
</Deeper>
