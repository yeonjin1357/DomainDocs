<KeyPoints>
  <Point title="프로세스는 실행 중인 프로그램이에요">
    프로세스마다 자기만의 메모리 공간이 있어요. 다른 프로세스의 메모리는 직접 볼 수 없어요.
  </Point>
  <Point title="스레드는 프로세스 안의 일꾼이에요">
    같은 프로세스의 스레드는 메모리를 함께 써요. 각자 실행 흐름만 따로 가져요.
  </Point>
  <Point title="운영체제가 CPU를 번갈아 맡겨요">
    실행할 준비가 된 스레드가 CPU 코어보다 많으면, 나머지는 차례를 기다려요.
  </Point>
</KeyPoints>

<Analogy limit="사람은 자기 일이 끝날 때까지 책상을 쓰지만, 운영체제는 한 스레드가 CPU를 오래 쥐지 못하게 차례를 번갈아 바꿔 줘요.">
  프로세스는 자기 방과 서류함을 가진 팀이에요. 스레드는 그 팀의 팀원이라, 같은 방의 서류를 함께 봐요. 관리자(운영체제)는 비어 있는 책상(CPU 코어)에 팀원을 번갈아 앉혀요.
</Analogy>

<Term term="server/process">프로세스</Term>는 실행 중인 프로그램이에요. 프로세스마다 번호(PID)가 붙고, 자기만의 메모리 공간을 받아요. 프로세스가 새 프로세스를 만들어도, 둘은 서로 다른 메모리 공간에서 돌아요.

<Term term="server/thread">스레드</Term>는 프로세스 안의 실행 흐름이에요. 한 프로세스에 스레드가 여럿 있으면, 모두 같은 프로그램을 실행하고 같은 메모리를 함께 써요. 스레드마다 따로 가진 건 지금 어디까지 실행했는지 담은 스택이에요.

그래서 스레드끼리는 데이터를 쉽게 나눠요. 대신 한 스레드가 공유 메모리를 망가뜨리면 같은 프로세스의 다른 스레드도 영향을 받아요.

DB도 연결을 프로세스로 맡을지 스레드로 맡을지 DB마다 달라요. 자세한 건 <Term slug="database/connections-and-sessions">연결과 세션</Term>에서 봐요.

## CPU는 차례로 써요

CPU 코어 하나는 한 번에 스레드 하나만 실행해요. 실행할 준비가 된 스레드가 코어보다 많으면, 커널의 <Term term="server/scheduler">스케줄러</Term>가 다음에 실행할 스레드를 골라요. 나머지는 실행 대기 줄에서 기다려요.

스레드가 늘 CPU를 원하는 건 아니에요. 디스크나 네트워크의 응답을 기다리는 동안에는 잠들어 있다가, 응답이 오면 다시 줄에 서요.

| 상태 | `ps` 표시 | 뜻 |
| --- | --- | --- |
| 실행 중·대기 | R | 실행 중이거나 실행 대기 줄에 있어요 |
| 잠듦 | S | 무언가를 기다리며 잠들어 있어요 |
| 깨울 수 없는 잠 | D | 보통 디스크 입출력을 기다려요 |
| 좀비 | Z | 끝났지만 부모 프로세스가 아직 거두지 않았어요 |

<Deeper>
  ### 스레드가 함께 쓰는 것

  POSIX는 한 프로세스의 스레드가 함께 쓰는 속성을 정해 둬요. 프로세스 ID, 부모 프로세스 ID, 열어 둔 파일 같은 것들이에요. 스레드마다 따로인 것은 스택처럼 실행 흐름에 딸린 것들이에요.

  ### /proc에서 스레드 보기

  리눅스에서 `/proc/<PID>/task` 폴더에는 그 프로세스의 스레드마다 하위 폴더가 하나씩 있어요. 스레드 수를 세는 도구들은 이런 커널 정보를 읽어요.

  ### 스케줄러

  리눅스 스케줄러는 실행할 수 있는 스레드 중 다음에 CPU에서 돌릴 스레드를 골라요. 보통의 스레드는 nice 값으로 우선순위를 조금씩 조정할 수 있어요.
</Deeper>
