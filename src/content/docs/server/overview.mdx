  서버는 사무실과 비슷해요. 직원(CPU 코어)이 책상(메모리)에서 서류를 펴 놓고 일하고, 오래 둘 서류는 캐비닛(디스크)에 넣어요. 관리자(운영체제)는 누가 언제 어느 책상을 쓸지 정해요.
</Analogy>

서버에서 돌아가는 프로그램은 모두 <Term term="server/process">프로세스</Term>예요. 프로세스가 파일을 읽거나 네트워크로 보내려면 <Term term="server/system-call">시스템 콜</Term>로 <Term term="server/kernel">커널</Term>에 부탁해요.

커널은 운영체제의 핵심이에요. 여러 프로세스가 CPU를 번갈아 쓰게 일정을 짜고, 메모리를 나눠 주고, 디스크와 네트워크 입출력을 대신해 줘요.

## 자원 네 가지

서버 모니터링 화면이 보여 주는 숫자는 대부분 이 네 자원에서 와요.

| 자원 | 하는 일 | 자주 보는 숫자 |
| --- | --- | --- |
| CPU | 계산 | 사용률, 부하 |
| 메모리 | 지금 쓰는 데이터를 둠 | 사용량, 스왑 |
| 디스크 | 오래 둘 데이터를 둠 | 읽기·쓰기 양, 지연, 용량 |
| 네트워크 | 다른 서버와 주고받음 | 주고받은 양, 에러 |

자원마다 얼마나 바쁜지(사용률), 일이 밀렸는지(포화), 에러가 났는지를 나눠 보면 원인을 빨리 좁혀요. 이 보는 법은 <Term slug="foundations/red-and-use">RED와 USE</Term>에서 다뤄요.

## 숫자는 커널에서 와요

리눅스 커널은 자기 상태를 `/proc`라는 가상 파일로 내놓아요. 실제 디스크에 있는 파일이 아니라, 읽을 때마다 커널이 지금 값을 만들어 줘요.

CPU가 어떤 일에 시간을 썼는지는 `/proc/stat`에, 부하는 `/proc/loadavg`에 있어요. 이 값 대부분은 부팅 뒤 계속 쌓이는 누적값이라, 사용률은 두 시점의 차이로 계산해요. 누적값을 다루는 법은 <Term slug="foundations/counters-and-rate">카운터와 rate</Term>에 있어요.

## 단계를 하나씩 확대해 봐요

이 영역은 리눅스를 기준으로 설명해요.

- 프로세스와 스레드가 CPU를 나눠 쓰는 법은 <Term slug="server/processes-and-threads">프로세스와 스레드</Term>에서 다뤄요.
- CPU 숫자를 읽는 법은 <Term slug="server/cpu-usage">CPU 사용률과 부하</Term>에서 다뤄요.
- 메모리 숫자와 스왑, OOM은 <Term slug="server/memory">메모리</Term>에서 다뤄요.
- 디스크가 얼마나 바쁜지는 <Term slug="server/disk-io">디스크 입출력</Term>에서 다뤄요.
- 디스크가 차는 여러 방식은 <Term slug="server/filesystem-and-capacity">파일 시스템과 디스크 용량</Term>에서 다뤄요.
- 서비스가 어떻게 뜨고 로그가 어디에 모이는지는 <Term slug="server/services-and-logs">서비스와 시스템 로그</Term>에서 다뤄요.
- 커널의 숫자가 모니터링 화면까지 오는 길은 <Term slug="server/metrics-sources">서버 지표는 어디서 오나</Term>에서 다뤄요.
