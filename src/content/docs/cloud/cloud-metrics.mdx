## 무엇을 모으나

클라우드 사업자는 서비스마다 기본 지표를 자동으로 모아요. 가상 머신의 CPU 사용률, 로드 밸런서의 요청 수, DB의 연결 수 같은 것들이에요. AWS에서는 CloudWatch, Azure에서는 Azure Monitor가 이 일을 해요.

이 지표는 서비스 바깥에서 잰 값이에요. 가상 머신 안의 메모리 사용률이나 앱의 응답시간은 기본 지표에 없어서, 에이전트나 앱이 직접 보내 줘야 해요. 이렇게 직접 보낸 지표를 사용자 지정 지표(custom metric)라고 해요.

## 지표의 이름표

CloudWatch에서 지표 하나는 세 가지 이름표로 가려요.

| 이름표 | 뜻 | 예 |
| --- | --- | --- |
| 네임스페이스 | 지표를 담는 그릇이에요. 서비스마다 따로 있어요 | `AWS/EC2` |
| 지표 이름 | 무엇을 쟀는지예요 | `CPUUtilization` |
| 차원 | 어느 대상을 쟀는지 나누는 이름=값이에요 | `InstanceId=i-0abc…` |

네임스페이스가 다르면 서로 섞이지 않아요. 차원은 지표의 정체성 일부라서, 차원 값이 다르면 다른 지표예요. 지표 하나에 차원을 30개까지 붙일 수 있어요.

이름표와 시계열의 관계는 <Term slug="foundations/time-series-and-labels">시계열과 레이블</Term>에서 다뤄요.

## 통계와 기간

지표는 일정한 기간마다 묶어서 통계로 봐요. 1분 동안 모인 값을 평균(Average), 합(Sum), 최댓값(Maximum), 백분위수 같은 통계로 줄여요.

어떤 통계를 고르느냐에 따라 같은 지표도 다르게 보여요. 요청 수나 에러 수처럼 세는 지표는 합으로 봐요. CPU 사용률 같은 값은 평균과 최댓값을 함께 봐야 짧은 급등을 놓치지 않아요.

## 오래될수록 거칠어져요

CloudWatch는 자료를 오래 둘수록 더 큰 단위로 묶어 남겨요.

| 처음 간격 | 그대로 볼 수 있는 기간 |
| --- | --- |
| 60초 미만(고해상도) | 3시간 |
| 1분 | 15일 |
| 5분 | 63일 |
| 1시간 | 455일(15개월) |

1분 간격으로 모은 자료는 15일 동안 1분 단위로 보여요. 15일이 지나면 5분 단위로 묶이고, 63일이 지나면 1시간 단위로 묶여요.

## 경보

CloudWatch 경보는 지표를 기간마다 보고 세 가지 상태 중 하나가 돼요.

| 상태 | 뜻 |
| --- | --- |
| OK | 지표가 정한 기준 안에 있어요 |
| ALARM | 지표가 정한 기준을 벗어났어요 |
| INSUFFICIENT_DATA | 막 만들었거나, 지표가 없거나, 판단할 자료가 모자라요 |

경보는 최근 N개 기간 중 M개가 기준을 넘으면 울려요. 예를 들어 1분 기간으로 "5개 중 4개"를 걸면, 최근 5분을 보고 그중 4분이 넘었을 때 울려요. 경보 조건을 짜는 법은 <Term slug="foundations/alert-conditions">알림 조건</Term>에서 다뤄요.

## 모니터링에서는

모니터링 제품은 클라우드 지표를 사업자의 API로 가져와 다른 지표와 함께 보여 줘요. 그래서 클라우드 지표는 사업자가 모은 간격과 통계를 그대로 따라요. 이 API 호출에도 요금이 붙는 이야기는 <Term slug="cloud/costs">클라우드 비용</Term>에 있어요.

같은 서버의 숫자도 어디서 왔는지에 따라 달라요. 콘솔의 5분 평균, 에이전트의 1분 값, OS 안의 순간값은 서로 다를 수 있어요. 숫자를 비교할 때는 간격과 통계를 먼저 맞춰요.

</Checkpoints>

<Deeper>
  ### 경보 평가 기간의 한도

  경보가 보는 전체 기간은 "기간 × 평가할 기간 수"예요. 기간이 1시간 이상이면 최대 7일, 그보다 짧으면 최대 1일까지 볼 수 있어요.

  ### Azure의 게스트 OS 지표

  Azure도 가상 머신 안의 지표는 에이전트로 모아요. 예전 Log Analytics 에이전트는 2024년 8월에 지원이 끝나, 지금은 Azure Monitor Agent를 써요.
</Deeper>
