## 인스턴스

AWS에서는 가상 머신을 <Term term="cloud/instance">인스턴스</Term>라고 불러요. EC2 인스턴스는 AWS 클라우드 안의 가상 서버예요. 물리 서버 한 대 위에서 여러 고객의 가상 서버가 함께 돌아요.

인스턴스를 만들 때는 이미지를 골라요. AWS의 AMI는 운영체제와 기본 소프트웨어를 묶은 서버 틀이에요. 같은 이미지로 만들면 같은 상태의 서버가 떠요.

인스턴스의 CPU는 vCPU(가상 CPU)로 세요. 인스턴스 안에 들어가면 보통의 서버와 같아서, CPU·메모리를 읽는 법도 <Term slug="server/cpu-usage">CPU 사용률</Term>과 같아요.

자주 보는 시리즈는 몇 개뿐이에요.

| 시리즈 | 용도 | 맞는 일 |
| --- | --- | --- |
| M | 범용 | CPU와 메모리를 고르게 쓰는 일 |
| C | 컴퓨트 최적화 | 계산이 많은 일 |
| R | 메모리 최적화 | 메모리를 많이 쓰는 데이터베이스, 캐시 |
| T | 버스트형 | 평소엔 한가하고 가끔 바쁜 일 |
| I | 저장소 최적화 | 디스크 읽기·쓰기가 많은 일 |

Azure에서는 같은 개념을 VM 크기(size)라고 불러요. 이름 규칙은 다르지만, 용도별 계열과 크기를 고른다는 점은 같아요.

## 버스트형 인스턴스와 CPU 크레딧

많은 서버는 평소에 한가하다가 가끔만 바빠요. T 시리즈 같은 <Term term="cloud/burstable-instance">버스트형 인스턴스</Term>는 이런 일에 맞춰 싸게 나온 유형이에요. 평소에는 기준선만큼의 CPU를 쓰고, 필요하면 기준선 위로 올라가요.

기준선 위로 올라가는 힘은 CPU 크레딧에서 나와요. 인스턴스는 돌아가는 동안 크레딧을 꾸준히 벌어요. 기준선보다 덜 쓰면 크레딧이 쌓이고, 더 쓰면 쌓인 크레딧을 꺼내 써요.

크레딧 1개는 vCPU 하나를 1분 동안 100% 쓰는 양이에요. 예를 들어 t3.large의 기준선은 30%예요. 30%보다 높게 오래 쓰면 크레딧이 줄어들어요.

크레딧이 바닥났을 때의 동작은 모드에 따라 달라요.

| 모드 | 크레딧이 바닥나면 |
| --- | --- |
| Standard | CPU가 기준선으로 서서히 내려와요. 크레딧이 다시 쌓일 때까지 더 오르지 못해요 |
| Unlimited | 계속 기준선 위로 써요. 대신 24시간 평균이 기준선을 넘으면 추가 요금을 내요 |

T3, T4g 같은 최신 세대는 Unlimited가 기본이고, 옛 T2는 Standard가 기본이에요.

## 켜고, 멈추고, 지우기

인스턴스는 실행 중, 중지, 종료 같은 상태를 오가요.

| 상태 | 요금 | 데이터 |
| --- | --- | --- |
| 실행 중 | 인스턴스 요금이 나와요 | 그대로예요 |
| 중지 | 인스턴스 요금은 안 나와요. 붙은 EBS 디스크 요금은 나와요 | EBS 디스크는 남고, 인스턴스 스토어는 지워져요 |
| 종료 | 더 나오지 않아요 | 인스턴스가 사라지고, 루트 디스크도 기본으로 지워져요 |

인스턴스 스토어는 호스트 서버에 붙은 임시 디스크예요. 다시 시작(reboot)은 같은 호스트에서 OS만 다시 켜서 데이터가 남아요. 하지만 중지했다가 켜면 다른 호스트로 옮겨질 수 있어서 인스턴스 스토어의 데이터가 지워져요.

클라우드 콘솔은 인스턴스마다 CPU 사용률, 네트워크, 디스크 같은 기본 지표를 보여 줘요. 기본 설정에서는 5분 간격이고, 추가 요금을 내고 상세 모니터링을 켜면 1분 간격이 돼요.

기본 지표 목록에는 메모리 사용률이 없어요. 메모리나 파일 시스템 사용률처럼 OS 안에서만 보이는 값은, 인스턴스 안에 에이전트를 깔아서 모아요.

<Deeper>
  ### CPU 사용률이 다른 이유

  EC2의 CPUUtilization은 물리 CPU 시간 중 그 인스턴스를 돌리는 데 쓴 비율이에요. 사용자 코드뿐 아니라 EC2 쪽 코드를 돌린 시간도 들어 있어요. 그래서 OS 도구가 보여 주는 값과 다를 수 있어요.

  ### 기준선 계산

  AWS 문서는 기준선을 "번 크레딧 ÷ vCPU 수 ÷ 60분"으로 계산해요. 크레딧을 버는 만큼만 쓰면 잔량이 늘지도 줄지도 않는 사용률이에요.
</Deeper>
