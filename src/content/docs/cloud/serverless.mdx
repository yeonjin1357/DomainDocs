## 서버리스 함수란

<Term term="cloud/serverless">서버리스 함수</Term>는 서버를 빌리지 않고 코드만 올려 실행하는 방식이에요. AWS Lambda, Azure Functions가 대표적이에요. 서버 유지 보수, 용량 준비, 확장, 패치를 사업자가 맡아요.

함수는 이벤트에 반응해 실행돼요. API 요청, 저장소에 파일이 올라옴, 큐에 메시지가 들어옴 같은 일이 이벤트예요. 실행 하나하나는 서로 상태를 나누지 않고 따로 돌아요.

요금은 쓴 만큼 내요. 요청이 없으면 실행도 없어서, 가끔 도는 일에 특히 싸요.

## 실행 환경과 콜드 스타트

Lambda는 함수를 실행 환경 안에서 돌려요. 요청이 왔는데 쓸 수 있는 실행 환경이 없으면 새로 만들어요. 코드를 내려받고 환경을 띄운 뒤, 핸들러 바깥의 초기화 코드를 먼저 실행해요.

이 준비 단계를 흔히 <Term term="cloud/cold-start">콜드 스타트</Term>라고 불러요. 준비 시간에도 요금이 붙고, 그만큼 응답이 늦어져요.

실행이 끝난 환경은 얼려 둔 채 잠시 남아요. 그사이 같은 함수에 요청이 오면 그 환경을 다시 써서 빨리 끝나요. 이걸 웜 스타트라고 해요.

AWS는 콜드 스타트가 보통 실행의 1% 미만이고, 길이는 100ms 미만부터 1초 넘게까지 다양하다고 해요. 요청이 드문 개발·테스트 함수에서 더 자주 생겨요. 시작 시간이 늘 일정해야 한다면, 실행 환경을 미리 띄워 두는 Provisioned Concurrency를 써요.

## 동시성과 스로틀

<Term term="cloud/concurrency">동시성</Term>은 함수가 같은 시각에 처리하고 있는 요청 수예요. 동시 요청마다 실행 환경이 하나씩 따로 떠요. AWS가 주는 대략적인 계산식은 이래요.

```text
동시성 = 초당 요청 수 × 평균 실행 시간(초)
```

<Figure caption="초당 400건이 오는데 한 건에 3초씩 걸리면 동시성은 1,200이에요. 리전의 기본 한도 1,000을 넘어, 넘친 요청은 스로틀돼요.">
  <StatTile label="초당 요청" value="400" unit="건" />
  <StatTile label="평균 실행 시간" value="3" unit="초" />
  <StatTile label="필요한 동시성" value="1,200" tone="warn" note="한도 1,000" />
</Figure>

AWS는 계정마다 리전 안의 모든 함수를 합쳐 기본 1,000개의 동시 실행 한도를 줘요. 쓸 수 있는 동시성이 없으면 Lambda는 더 들어온 요청을 거절해요. 이걸 스로틀이라고 해요.

이 한도는 리전 안의 모든 함수가 함께 써요. 그래서 함수 하나가 몰리면 다른 함수까지 스로틀될 수 있어요. 중요한 함수에는 함수 단위로 동시성을 따로 떼어 둬요.

실행 시간에도 한도가 있어요. Lambda 함수의 기본 제한 시간은 3초이고, 최대 900초(15분)까지 늘릴 수 있어요.

## 모니터링에서는

Lambda는 함수마다 이런 지표를 내보내요.

| 지표 | 뜻 |
| --- | --- |
| Invocations | 함수가 호출된 수예요. 스로틀된 요청은 들어가지 않아요 |
| Errors | 함수 오류로 끝난 호출 수예요. 제한 시간 초과도 들어가요 |
| Throttles | 스로틀된 요청 수 |
| Duration | 함수 코드가 이벤트를 처리한 시간이에요. 콜드 스타트 시간은 빠져요 |
| ConcurrentExecutions | 지금 이벤트를 처리 중인 실행 환경 수 |

함수에는 서버가 없으니, CPU·메모리 대신 호출 수, 오류, 실행 시간, 동시성을 봐요. 동시성이 한도에 다가가는지가 용량 문제의 첫 신호예요.

<Checkpoints>
  <Check>Duration이 짧은데 사용자가 느리다고 한다면 콜드 스타트를 의심해 보세요. Duration에는 콜드 스타트 시간이 들어가지 않아요.</Check>
  <Check>오류율을 Errors ÷ Invocations로만 계산한다면 다시 보세요. 스로틀된 요청은 Invocations에도 Errors에도 들어가지 않아요. Throttles를 따로 봐요.</Check>
  <Check>함수 하나만 바쁜데 다른 함수까지 스로틀된다면, 리전의 동시성 한도를 함께 쓰고 있는 거예요.</Check>
  <Check>실행 환경의 메모리나 /tmp에 남긴 값을 다음 호출에서 꼭 쓸 수 있다고 믿었다면 다시 보세요. 실행 환경은 언제든 새로 바뀔 수 있어요.</Check>
</Checkpoints>

<Deeper>
  ### 실행 환경은 몇 시간마다 바뀌어요

  AWS 문서는 계속 호출되는 함수라도 런타임 업데이트와 유지 보수를 위해 몇 시간마다 실행 환경을 끝낸다고 해요. 그래서 함수는 상태를 남기지 않게 만들어요.

  ### 초기화 단계의 시간 제한

  초기화 단계는 10초로 제한돼요. 10초 안에 끝나지 않으면, 첫 호출 때 함수의 제한 시간을 걸고 초기화를 다시 시도해요.

  ### Azure Functions

  Azure Functions도 서버를 배포하고 관리하는 대신, 클라우드가 실행에 필요한 자원을 대 주는 서버리스 방식이에요.
</Deeper>
