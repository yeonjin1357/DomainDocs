## 1. 어느 검사가 실패했는지 보세요

EC2는 인스턴스마다 매분 상태 검사를 해요. 모두 통과하면 OK, 하나라도 실패하면 impaired예요. 실패한 검사는 지표로도 남아요.

| 검사 | 보는 것 | 실패하면 |
| --- | --- | --- |
| 시스템 검사 | 인스턴스가 도는 AWS 쪽 시스템 | 2단계. AWS 쪽 문제예요 |
| 인스턴스 검사 | 인스턴스의 소프트웨어와 네트워크 설정 | 3단계. 보통 내가 고쳐야 해요 |
| 붙은 EBS 검사 | 붙은 디스크에 닿아 읽고 쓸 수 있는지 | 디스크를 바꾸거나 멈췄다 켜요 |

**확인 방법**: StatusCheckFailed_System과 StatusCheckFailed_Instance 지표를 봐요. 둘 다 지난 1분 동안 통과했으면 0, 실패했으면 1이에요.

## 2. 시스템 검사 실패라면 옮겨 띄우세요

시스템 검사는 물리 호스트 쪽 문제를 잡아요. AWS 문서는 네트워크 연결이 끊기거나, 전원이 나가거나, 물리 호스트의 소프트웨어·하드웨어에 문제가 생긴 경우를 꼽아요.

AWS가 고칠 때까지 기다릴 수도 있고, 직접 옮길 수도 있어요. EBS로 부팅하는 인스턴스는 멈췄다 다시 켜면 대개 새 호스트로 옮겨져요. 이때 인스턴스 스토어의 데이터는 지워져요.

## 3. 인스턴스 검사 실패라면 서버 안을 보세요

인스턴스 검사는 서버 안의 문제를 잡아요. AWS 문서가 꼽는 예는 이래요.

- 시스템 검사가 함께 실패했어요.
- 네트워크나 부팅 설정이 잘못됐어요.
- 메모리를 다 써 버렸어요.
- 파일 시스템이 깨졌어요.
- 커널이 맞지 않아요.

## 4. 같은 일이 되풀이되지 않게 하세요

상태 검사 지표에 경보를 걸어 두면, 사람이 알아채기 전에 알 수 있어요. 시스템 검사 실패에는 자동 복구를 걸어 둘 수도 있어요. 자동 복구는 같은 설정으로 인스턴스를 새 호스트에 옮겨 띄워요.

인스턴스 검사 실패가 되풀이된다면, 메모리 한도나 디스크 정리처럼 원인을 고쳐야 해요. 자동 복구로는 서버 안의 문제가 고쳐지지 않아요.
