## 누가 무엇을 맡나

<Term term="cloud/managed-database">관리형 데이터베이스</Term>는 사업자가 DB 운영의 큰 부분을 맡아 주는 서비스예요. AWS RDS, Azure SQL Database가 대표적이에요. 같은 DB를 가상 머신에 직접 설치해 쓸 때와 비교하면 차이가 분명해요.

| 할 일 | 가상 머신에 직접 설치 | RDS |
| --- | --- | --- |
| 쿼리·앱 최적화 | 내가 | 내가 |
| 크기 조정, 고가용성 | 내가 | AWS |
| DB 백업 | 내가 | AWS |
| DB 설치·패치 | 내가 | AWS |
| OS 설치·패치 | 내가 | AWS |
| 서버·하드웨어 | AWS | AWS |

AWS 문서는 쿼리 튜닝은 고객 책임이라고 분명히 적어요. 쿼리 성능은 DB 설계, 데이터 크기와 분포, 앱의 부하에 따라 크게 달라지기 때문이에요. DB가 쿼리를 처리하는 방식은 <Term slug="database/overview">쿼리 하나가 DB를 지나가는 길</Term>에서 다뤄요.

## 다중 AZ: 장애 대비용 대기 서버

RDS의 다중 AZ 배포는 다른 가용 영역에 대기 서버를 자동으로 두고 유지해요. 주 서버의 변경은 대기 서버에 동기로 복제돼요. 주 서버나 그 가용 영역에 문제가 생기면 대기 서버가 넘겨받아요.

다만 대기 서버는 읽기 요청을 받지 않아요. AWS는 고가용성 설정이 읽기를 늘리는 방법이 아니라고 적어요. 읽기를 나누려면 읽기 복제본을 따로 써요.

## 읽기 복제본

읽기 복제본은 주 DB의 읽기 전용 사본이에요. 앱의 읽기 쿼리를 복제본으로 보내 주 DB의 부담을 덜어요. 복제본도 일반 DB 인스턴스와 같은 요금을 내요.

읽기 복제본은 DB 엔진의 비동기 복제로 주 DB를 따라가요. 그래서 방금 쓴 데이터가 복제본에는 아직 없을 수 있어요. 복제와 지연은 DB의 <Term slug="database/replication">복제</Term>와 <Term slug="database/replication-lag">복제 지연</Term>에서 다뤄요.

## 유지 보수 시간

관리형 DB도 가끔 패치와 업그레이드가 필요해요. RDS는 주기적으로 유지 보수를 하고, 정해 둔 유지 보수 시간(maintenance window)에 적용해요. 바로 적용하지 않기로 한 설정 변경도 이 시간에 적용돼요.

보안·안정성 패치 같은 일부 유지 보수는 DB를 잠깐 멈추고 해요. 다중 AZ라면 대기 서버를 먼저 손본 뒤 주 서버로 올려서 멈추는 시간을 줄여요. 그래도 유지 보수 시간은 사용자가 가장 적은 시간대로 정해 둬요.

## 모니터링에서는

관리형 DB도 클라우드 지표 서비스로 기본 지표를 내보내요. RDS에서 자주 보는 지표는 이래요.

| 지표 | 뜻 |
| --- | --- |
| CPUUtilization | CPU 사용률 |
| DatabaseConnections | DB에 붙은 클라이언트 네트워크 연결 수 |
| FreeableMemory | 쓸 수 있는 메모리 |
| FreeStorageSpace | 남은 저장 공간 |
| ReadIOPS, ReadLatency | 초당 디스크 읽기 수, 읽기 한 번에 걸린 시간 |
| ReplicaLag | 읽기 복제본이 주 DB보다 늦은 정도 |

관리형 DB는 OS에 직접 들어가 볼 수 없어서, OS 수준의 숫자는 사업자가 주는 기능으로 봐요. RDS의 Enhanced Monitoring은 DB 인스턴스 안의 에이전트가 OS 지표를 모아요.

  <Check>다중 AZ 대기 서버로 읽기 부하를 나눌 수 있다고 여겼다면 다시 보세요. 대기 서버는 읽기를 받지 않아요. 읽기 복제본을 따로 써요.</Check>

  <Check>버스트형(db.t 계열) DB의 CPU 크레딧(CPUCreditBalance)이 바닥났다면 요금을 보세요. RDS의 db.t3·db.t4g는 Unlimited 모드라 CPU가 기준선에 묶이지 않고, 넘게 쓴 몫에 요금이 붙을 수 있어요.</Check>

<Deeper>
  ### CPU 숫자가 두 가지인 이유

  CloudWatch의 CPU 사용률은 하이퍼바이저에서 재고, Enhanced Monitoring은 인스턴스 안의 에이전트가 재요. 하이퍼바이저가 하는 일이 조금 있어서 둘이 달라요. 작은 인스턴스일수록 차이가 커질 수 있어요.

  ### FreeableMemory의 출처

  MariaDB, MySQL, Oracle, PostgreSQL에서는 FreeableMemory가 곧 MemAvailable 값이에요. 리눅스의 `/proc/meminfo`에 있는 값이에요. 이 값의 뜻은 서버·OS의 <Term slug="server/memory">메모리</Term>에서 다뤄요.

  ### Azure SQL Database

  Azure SQL Database도 고가용성, 백업, 유지 보수를 서비스가 맡아요. Microsoft가 SQL과 운영체제의 패치·업데이트를 모두 처리해요.
</Deeper>
