<Analogy limit="택배는 상자 하나가 그대로 끝까지 가지만, 네트워크 데이터는 잘게 나뉜 패킷 여러 개로 가고, 패킷마다 다른 길로 갈 수도 있어요.">
  네트워크는 택배와 비슷해요. 상자(패킷)에 보내는 곳과 받는 곳의 주소를 적어요. 같은 건물 안이면 건물 우편실(스위치)이 바로 전해 주고, 다른 동네면 우체국(라우터)이 다음 우체국으로 넘겨요.
</Analogy>

1. **보내기**: 서버 A의 앱이 데이터를 보내면, 운영체제가 받는 곳의 주소를 붙여 <Term term="network/interface">인터페이스</Term>(네트워크 카드)로 내보내요.
2. **같은 네트워크 안**: <Term term="network/switch">스위치</Term>가 받는 쪽 장비가 어느 포트에 있는지 보고 그 포트로 넘겨요.
3. **네트워크 사이**: 받는 곳이 다른 네트워크라면 <Term term="network/router">라우터</Term>가 경로표를 보고 다음 장비로 넘겨요.
4. **받기**: 서버 B가 있는 네트워크의 스위치가 서버 B에게 전해 주고, 서버 B의 운영체제가 맞는 앱에 넘겨요.

인터넷 프로토콜(IP)은 데이터를 데이터그램(패킷)이라는 덩어리로 나눠, 주소로 가리킨 곳까지 보내요. 문서는 이름은 무엇을 찾는지, 주소는 어디 있는지, 경로는 어떻게 가는지를 뜻한다고 나눠 말해요.

## 네트워크 장비들

| 장비 | 하는 일 |
| --- | --- |
| 스위치 | 같은 네트워크 안의 장비끼리 데이터를 넘겨요 |
| 라우터 | 서로 다른 네트워크 사이로 데이터를 넘겨요 |
| 방화벽 | 정해 둔 규칙에 따라 통신을 막거나 통과시켜요 |
| 로드 밸런서 | 들어온 요청을 여러 서버에 나눠 줘요 |

장비마다 데이터가 드나드는 구멍(포트)이 여러 개 있어요. 장비 쪽에서는 이 구멍 하나하나를 인터페이스라고 불러요. 네트워크 장비 모니터링은 대부분 이 인터페이스마다 무엇이 오가는지 보는 일이에요.

## 단계를 하나씩 확대해 봐요

- 받는 곳을 가리키는 세 가지 주소는 <Term slug="network/addresses">주소: IP, MAC, 포트</Term>에서 다뤄요.
- 이름을 IP 주소로 바꾸는 법은 <Term slug="network/dns">DNS</Term>에서 다뤄요.
- 스위치와 라우터가 데이터를 넘기는 법은 <Term slug="network/switches-and-routers">스위치와 라우터</Term>에서 다뤄요.
- 인터페이스마다 오간 양을 세는 법은 <Term slug="network/interfaces-and-traffic">인터페이스와 트래픽</Term>에서 다뤄요.
- 장비에서 값을 물어 가져오는 법은 <Term slug="network/snmp">SNMP</Term>에서 다뤄요.
- 장비가 먼저 보내는 알림은 <Term slug="network/traps-and-syslog">SNMP Trap과 Syslog</Term>에서 다뤄요.
- 누가 누구와 얼마나 주고받았는지는 <Term slug="network/flows">흐름 정보(NetFlow·sFlow)</Term>에서 다뤄요.
- 서버끼리 연결을 맺고 데이터를 빠짐없이 전하는 법은 <Term slug="network/tcp-connections">TCP 연결</Term>에서 다뤄요.
- 통신을 거르고 주소를 바꾸는 장비는 <Term slug="network/firewalls-and-nat">방화벽과 NAT</Term>에서 다뤄요.
- 장비가 살아 있는지와 지연·손실을 재는 법은 <Term slug="network/ping-and-latency">ping과 지연·손실</Term>에서 다뤄요.
- 서버가 진짜인지 보여 주는 인증서와 그 만료는 <Term slug="network/tls-certificates">TLS 인증서와 만료</Term>에서 다뤄요.
