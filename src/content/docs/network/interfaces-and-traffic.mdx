## 인터페이스가 세는 것

<Term term="network/interface">인터페이스</Term>마다 세는 값은 IF-MIB라는 표준에 정해져 있어요. SNMP로 읽을 때 쓰는 이름 그대로 적었어요.

| 이름 | 뜻 |
| --- | --- |
| ifInOctets, ifOutOctets | 받은·보낸 바이트(32비트 카운터) |
| ifHCInOctets, ifHCOutOctets | 같은 값을 64비트로 센 카운터 |
| ifInErrors | 에러가 있어 위로 넘기지 못한 받은 패킷 수 |
| ifInDiscards | 에러는 없었지만 버린 받은 패킷 수 |
| ifSpeed, ifHighSpeed | 인터페이스 속도(bps, ifHighSpeed는 Mbps 단위) |
| ifAdminStatus | 관리자가 정한 상태(켬·끔) |
| ifOperStatus | 지금 실제 동작 상태 |

## bps와 사용률

바이트 카운터는 늘어나기만 하는 누적값이에요. 그래서 트래픽은 두 번 읽은 차이로 계산해요. 누적값을 다루는 법은 <Term slug="foundations/counters-and-rate">카운터와 rate</Term>와 같아요.

예를 들어 1Gbps 인터페이스의 ifHCInOctets를 60초 간격으로 읽었더니 3,750,000,000 늘었다고 해 봐요. 바이트에 8을 곱하면 비트예요. 3,750,000,000 × 8 ÷ 60 = 500,000,000bps, 곧 500Mbps예요.

<Term term="network/link-utilization">사용률</Term>은 이 값을 인터페이스 속도로 나눠요. 500Mbps ÷ 1Gbps = 50%예요. 보통 받는 쪽과 보내는 쪽이 동시에 각자 속도만큼 쓸 수 있어서, 사용률도 방향마다 따로 계산해요.

## 32비트 카운터는 한 바퀴 돌아요

32비트 카운터는 4,294,967,295까지 세고 0으로 돌아가요. 1Gbps는 초당 1억 2,500만 바이트라, 가득 오가면 약 34초면 한 바퀴를 돌아요.

<Figure caption="1Gbps로 가득 오갈 때 카운터가 한 바퀴 도는 시간이에요. 32비트로 1분마다 읽으면 그사이 한 바퀴 넘게 돌아 값이 틀려요.">

    rows={[

      { label: '1Gbps에서 한 바퀴', values: ['약 34초', '수천 년'] },
      { label: '10Gbps에서 한 바퀴', values: ['약 3.4초', '수백 년'] },
    ]}
  />
</Figure>

카운터를 읽는 간격보다 한 바퀴가 빠르면, 몇 바퀴 돌았는지 알 수 없어 트래픽이 틀려요. 그래서 표준은 빠른 인터페이스에 64비트 카운터를 두라고 해요. 1Gbps 같은 빠른 인터페이스는 ifHC로 시작하는 64비트 카운터로 읽어요.

장비를 다시 켜면 카운터는 0부터 다시 세요. 이때 차이를 그대로 계산하면 음수나 엄청나게 큰 값이 나와요.

## 에러와 버린 패킷, 상태

ifInErrors는 패킷에 에러가 있어 받지 못한 수예요. 흔히 케이블이나 포트 같은 물리 문제를 먼저 의심해요.

ifInDiscards는 에러는 없었지만 버린 수예요. 문서는 버퍼 공간을 비우려고 버리는 경우를 예로 들어요.

상태는 두 가지를 함께 봐요. 관리 상태(ifAdminStatus)는 관리자가 켜 두었는지, 동작 상태(ifOperStatus)는 실제로 통신이 되는지예요. 켜 두었는데 동작 상태가 down이라면 고장이고, 관리자가 꺼 둔 포트가 down인 건 정상이에요.

<Deeper>
  ### 표준이 정한 카운터 크기

  IF-MIB는 인터페이스 속도에 따라 필요한 카운터를 정해요. 20Mbps 이하면 32비트 바이트·패킷 카운터를 둬요. 650Mbps 이상이면 바이트와 패킷 카운터 모두 64비트를 둬야 해요.

  ### 빠른 인터페이스의 속도

  ifSpeed도 32비트라 약 4.29Gbps보다 빠른 속도는 담지 못해요. 그래서 이보다 빠른 인터페이스는 Mbps 단위인 ifHighSpeed로 속도를 읽어요.

  ### 카운터가 끊기는 때

  표준은 관리 시스템이 다시 시작될 때 카운터 값이 끊길 수 있다고 해요. 그 밖에 끊긴 때는 ifCounterDiscontinuityTime으로 알려 줘요.
</Deeper>
